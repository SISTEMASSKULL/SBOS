## 0. Principio rector

> **bNexus no es un cliente web ni una aplicación de usuario.**  
> bNexus es un **daemon soberano** que habla con bAuth mediante protocolos de daemon:  
> Unix sockets (Puerta 2A y B) y WebSocket mTLS (Puerta 1).  
> Ningún componente bNexus usa HTTP/TCP directo entre daemons (SBOS-050 P9).

El Motor de Canales (`motor-canales.md`, manual 2.12) define cómo el **daemon bAuth** gestiona sus
transportes desde el servidor. Este manual define el **SDK de integración bNexus**: el conjunto de
traits, adaptadores y sagas que el código Rust de bNexus implementa para comunicarse con bAuth y
entre sus propias capas.

**Tres relaciones de comunicación que este motor formaliza:**

| Relación | Protocolo | Manual de referencia |
|---------|-----------|---------------------|
| `banexus → bhnexus` | WebSocket mTLS (Puerta 1) | `BnexusAgent/2.01_MANUAL-PUERTA-1-AGENTES.md` |
| `bhnexus → bAuth` | Unix socket TLV (Puerta 2A) | `BnexusAgent/2.02_MANUAL-PUERTA-2-BAUTH.md` |
| `bAuth → bhnexus` | Unix socket push (Puerta 2B) | `BnexusAgent/2.02_MANUAL-PUERTA-2-BAUTH.md` §3 |

Los manuales de Puerta 1 y Puerta 2 describen **el protocolo de wire** (frames, TLV, handshake).  
**Este manual describe el código Rust** que implementa esos protocolos — el SDK de transporte.

## 1. Protocolo canónico: WebSocket + JSON-RPC 2.0

### 1.1 Por qué WebSocket en Puerta 1 (banexus ↔ bhnexus)

| Alternativa | Por qué no |
|-------------|-----------|
| HTTP/REST polling | No permite server push (decisiones auth en tiempo real). Latencia de polling inaceptable. |
| gRPC | Requiere `.proto` por método. Overhead de compilación. Sin ventaja sobre WS+JSON-RPC. |
| MQTT | No bidireccional request/response con correlación por ID. Pensado para telemetría, no auth. |
| WebSocket + JSON-RPC 2.0 | Bidireccional, full-duplex, multiplexado por `id`. Rustls (sin OpenSSL). Sin legacy cipher suites. |

### 1.2 Por qué Unix socket TLV en Puerta 2A (bhnexus → bAuth)

| Criterio | Unix socket TLV | HTTP/TCP |
|---------|----------------|---------|
| Seguridad | Solo procesos del mismo host — no entra red | Expone superficie de red |
| Latencia | <1ms — sin TCP handshake | 3-30ms por TLS handshake |
| Autenticación | Credenciales OS (uid/gid bos-group) | Requiere Bearer token o mTLS extra |
| SBOS-050 P9 | ✅ NUNCA HTTP/TCP entre daemons | ❌ Prohibido |

### 1.3 Estructura de URL / socket por entorno

| Componente | Desarrollo | Producción |
|-----------|-----------|-----------|
| Puerta 1 (banexus→bhnexus) | `wss://bhnexus-dev.local:9444` | `wss://bhnexus.sbos.local:9444` |
| Puerta 2A (bhnexus→bAuth) | `/run/bos/bauth.sock` (mismo) | `/run/bos/bauth.sock` (mismo) |
| Puerta 2B (bAuth→bhnexus) | `/run/bos/bauth-nexus.sock` (mismo) | `/run/bos/bauth-nexus.sock` (mismo) |
| Interface Dual bhnexus | `/run/bos/bhnexus.sock` (mismo) | `/run/bos/bhnexus.sock` (mismo) |

Los Unix sockets no cambian entre entornos — son paths del sistema. Solo las URLs de
WebSocket (Puerta 1) cambian al moverse entre entornos de desarrollo y producción.

## 2. El contrato permanente: `ITransporte`

Este trait es el artefacto más estable del motor. Se define una vez y nunca cambia.
Todo adaptador concreto (Unix socket, WebSocket, mock de tests) implementa este contrato.

```rust
// BnexusAgent/src/transport/i_transporte.rs
//
// Contrato permanente de transporte — NUNCA se añaden métodos sin ADR documentado.
// Tanto la Puerta 2A como la Puerta 1 implementan este trait.
#[async_trait]
pub trait ITransporte: Send + Sync {
    /// Envía un request y espera la respuesta. ctx_id se propaga en el payload.
    async fn llamar(
        &self,
        tipo: &str,
        payload: serde_json::Value,
        ctx_id: &str,
    ) -> Result<serde_json::Value, TransporteError>;

    /// Conecta al destino. Idempotente si ya está conectado.
    async fn conectar(&self) -> Result<(), TransporteError>;

    fn desconectar(&self);

    fn esta_conectado(&self) -> bool;
}

/// Errores canónicos del transporte — NUNCA usar String genérico.
#[derive(Debug, thiserror::Error)]
pub enum TransporteError {
    #[error("Timeout en operación: {0}")]
    Timeout(String),
    #[error("Socket no disponible: {0}")]
    SocketNoDisponible(String),
    #[error("Error de certificado mTLS: {0}")]
    CertificadoInvalido(String),
    #[error("Conexión cerrada inesperadamente")]
    ConexionCerrada,
    #[error("Error de protocolo: {0}")]
    Protocolo(String),
}
```

El equivalente en Flutter/Dart (para herramientas de administración que consuman bhnexus):

```dart
// Herramienta de admin / dashboard — NO es el daemon
abstract interface class ITransporteCliente {
  Future<Map<String, dynamic>> llamar(String metodo, [Map<String, dynamic>? params]);
  Future<void> conectar(ParametrosConexion params);
  void desconectar();
  Stream<EstadoConexion> get estado;
}
```

## 3. Las capas del SDK bNexus: stack aditivo

Cada capa agrega una capacidad sin modificar las capas previas. Lo construido en Capa N
**no se toca** en Capa N+1 — solo se agrega encima.

```
── Puerta 2A: bhnexus → bAuth ──────────────────────────────────────────

Capa 0  ITransporte                 Contrato permanente. NUNCA cambia.
  │
Capa 1  UnixSocketTransporte        Abre /run/bos/bauth.sock. Framing TLV.
  │     (Unix socket, bos-group)    Pool 100 conexiones. Timeout 1000ms.
  │                                 Sin autenticación extra — OS garantiza uid.
  │
Capa 2  BitmaskRequestAdapter       Envía bitmask_request, recibe bitmask_response.
  │                                 Convierte SAM-128 en AuthDecision tipada.
  │                                 Sin contacto con la Capa 1 concreta.
  │
Capa 3  AuthCacheDecorator          Cache in-memory HashMap<(user_id, node_id), CacheEntry>.
  │                                 TTL 30s. LRU 10K entradas. Capa 2 no sabe que existe.
  │
Capa 4  MetricsDecorator            Instrumenta llamadas: latencia, cache hit ratio.
                                    Prometheus via bhnexus_bauth_latency_ms.

── Puerta 2B: bAuth → bhnexus ───────────────────────────────────────────

Capa 0  ITransporte                 Mismo contrato.
  │
Capa B1 PriviledgedSocketListener   Crea /run/bos/bauth-nexus.sock (0660, bos-group).
  │                                 bAuth conecta como cliente. Loop de lectura.
  │
Capa B2 EventoPrivilegiadoRouter    Despacha eventos por tipo:
                                      emergency_revoke  → purgar cache + DENY activo
                                      blacklist_node    → desconectar banexus
                                      policy_update     → reenviar a banexus afectados

── Puerta 1: banexus → bhnexus ──────────────────────────────────────────

Capa 0  ITransporte                 Mismo contrato (lado servidor de bhnexus).
  │
Capa P1 WsServerMtls               Escucha en TCP 9444. TLS 1.3 rustls. mTLS SPIFFE.
  │                                 Extrae node_id del SPIFFE URI.
  │
Capa P2 AgentSessionManager        Registra la sesión del nodo. Heartbeat cada 30s.
  │                                 Desconexión limpia al timeout.
  │
Capa P3 AuthRequestDispatcher      Recibe auth_request. Decide cache hit/miss.
                                    Hit → responde en <2ms. Miss → Capa 2 Puerta 2A.
```

## 4. Implementaciones de referencia en Rust

### 4.1 `UnixSocketTransporte` — Puerta 2A

```rust
// BnexusAgent/src/transport/unix_socket_transporte.rs
//
// Adaptador de transporte sobre Unix socket para comunicación bhnexus → bAuth.
// Usa pool de conexiones (deadpool-tokio) para evitar crear/cerrar sockets por request.
pub struct UnixSocketTransporte {
    ruta_socket: PathBuf,
    pool:        Pool<UnixSocketManager>,
    timeout_ms:  u64,
}

impl UnixSocketTransporte {
    pub fn nuevo(ruta: &str, pool_max: usize, timeout_ms: u64) -> Result<Self, TransporteError> {
        let manager = UnixSocketManager::new(PathBuf::from(ruta));
        let pool = Pool::builder(manager).max_size(pool_max).build()?;
        Ok(Self { ruta_socket: PathBuf::from(ruta), pool, timeout_ms })
    }
}

#[async_trait]
impl ITransporte for UnixSocketTransporte {
    async fn llamar(&self, tipo: &str, payload: Value, ctx_id: &str) -> Result<Value, TransporteError> {
        let mut conn = self.pool.get().await
            .map_err(|_| TransporteError::SocketNoDisponible(self.ruta_socket.display().to_string()))?;

        let mut mensaje = payload;
        mensaje["type"]   = Value::String(tipo.to_string());
        mensaje["ctx_id"] = Value::String(ctx_id.to_string());

        let bytes = serde_json::to_vec(&mensaje)?;

        // Framing TLV: [4 bytes longitud big-endian][N bytes JSON]
        let longitud = (bytes.len() as u32).to_be_bytes();
        conn.write_all(&longitud).await?;
        conn.write_all(&bytes).await?;

        // Leer respuesta: [4 bytes longitud][N bytes JSON]
        let mut len_buf = [0u8; 4];
        timeout(Duration::from_millis(self.timeout_ms), conn.read_exact(&mut len_buf)).await
            .map_err(|_| TransporteError::Timeout(tipo.to_string()))??;

        let n = u32::from_be_bytes(len_buf) as usize;
        let mut resp_buf = vec![0u8; n];
        conn.read_exact(&mut resp_buf).await?;

        Ok(serde_json::from_slice(&resp_buf)?)
    }

    async fn conectar(&self) -> Result<(), TransporteError> {
        // El pool gestiona conexiones — conectar es no-op a nivel de pool.
        Ok(())
    }

    fn desconectar(&self) { /* pool cierra conexiones al hacer drop */ }

    fn esta_conectado(&self) -> bool {
        self.pool.status().available > 0
    }
}
```

### 4.2 `BitmaskRequestAdapter` — Puerta 2A Capa 2

```rust
// BnexusAgent/src/transport/bitmask_request_adapter.rs
//
// Traduce llamadas de alto nivel (resolver_acceso) al protocolo bitmask_request.
pub struct BitmaskRequestAdapter {
    transporte: Arc<dyn ITransporte>,
}

impl BitmaskRequestAdapter {
    /// Resuelve si un usuario tiene acceso en un nodo. Retorna AuthDecision con SAM-128.
    pub async fn resolver_acceso(
        &self,
        user_id:   Uuid,
        node_id:   &str,
        dominio:   &str,
        operacion: &str,
        ctx_id:    &str,
    ) -> Result<AuthDecision, TransporteError> {
        let payload = serde_json::json!({
            "request_id": Uuid::new_v4().to_string(),
            "user_id":    user_id.to_string(),
            "node_id":    node_id,
            "domain":     dominio,
            "operation":  operacion,
            "timestamp":  Utc::now().to_rfc3339(),
        });

        let resp = self.transporte
            .llamar("bitmask_request", payload, ctx_id)
            .await?;

        AuthDecision::desde_respuesta(resp)
    }
}

/// Decisión de autorización derivada del SAM-128.
pub struct AuthDecision {
    pub permitido:        bool,
    pub sam_128_word_a:   u64,
    pub sam_128_word_b:   u64,
    pub actuator_commands: Vec<ActuatorCommand>,
    pub expira_en:        DateTime<Utc>,
}
```

### 4.3 `PriviledgedSocketListener` — Puerta 2B Capa B1

```rust
// BnexusAgent/src/transport/priviledged_socket_listener.rs
//
// Crea el socket del canal privilegiado. bAuth conecta como cliente.
// bhnexus CREA el socket — bAuth lo usa, NO al revés.
pub struct PriviledgedSocketListener {
    ruta_socket: PathBuf,
    tx_eventos:  Sender<EventoPrivilegiadoBAuth>,
}

impl PriviledgedSocketListener {
    pub async fn iniciar(
        ruta: &str,
        tx:   Sender<EventoPrivilegiadoBAuth>,
    ) -> Result<(), TransporteError> {
        // Eliminar socket anterior si existe (evitar "Address already in use")
        let _ = fs::remove_file(ruta);

        let listener = UnixListener::bind(ruta)?;
        fs::set_permissions(ruta, Permissions::from_mode(0o660))?;

        log::info!("Canal privilegiado escuchando en {}", ruta);

        loop {
            let (stream, _) = listener.accept().await?;
            let tx_clone = tx.clone();
            tokio::spawn(Self::manejar_conexion_bauth(stream, tx_clone));
        }
    }

    async fn manejar_conexion_bauth(
        mut stream: UnixStream,
        tx: Sender<EventoPrivilegiadoBAuth>,
    ) {
        let mut buf = [0u8; 4096];
        loop {
            match stream.read(&mut buf).await {
                Ok(0) => { log::info!("bAuth cerró el canal privilegiado"); break; }
                Ok(n) => {
                    if let Ok(evento) = serde_json::from_slice::<EventoPrivilegiadoBAuth>(&buf[..n]) {
                        let _ = tx.send(evento).await;
                    }
                }
                Err(e) => { log::error!("Error en canal privilegiado: {e}"); break; }
            }
        }
    }
}

/// Eventos que bAuth puede empujar a bhnexus via canal B.
#[derive(Debug, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum EventoPrivilegiadoBAuth {
    EmergencyRevoke  { user_id: Uuid, scope: String, ctx_id: String },
    BlacklistNode    { node_id: String, reason: String, ctx_id: String },
    PolicyUpdate     { affected_nodes: Vec<String>, sam_delta: Value, ctx_id: String },
    CaepSessionEnded { user_id: Uuid, jti: String, ctx_id: String },
}
```

## 5. Sagas del motor de comunicación — bNexus

Las sagas describen los flujos compostos críticos. Cada saga tiene pasos secuenciales
y compensaciones en caso de error. Ver también `BnexusAgent/2.04_MANUAL-SAGAS-NEXUS.md`.

### 5.1 Saga de auth_request (flujo principal — bloqueante de UX)

```
EVENTO: banexus captura credencial (QR, NFC, RFID, PIN)

PASO 1: banexus → Puerta 1 → bhnexus
  payload: { type: "auth_request", credential: {...}, ctx_id: "00-trace-..." }
  timeout: 100ms (el usuario está esperando físicamente)
  ✓ bhnexus recibe el request

PASO 2: bhnexus consulta Auth Cache
  → AuthCacheDecorator.buscar(user_id, node_id)
  ✓ Cache HIT → SAM-128 vigente → saltar a PASO 4
  ✗ Cache MISS → continuar a PASO 3

PASO 3: bhnexus → Puerta 2A → bAuth
  → BitmaskRequestAdapter.resolver_acceso(user_id, node_id, dominio, operación, ctx_id)
  timeout: 10ms (sub-canal A pool 100 conexiones)
  ✓ SAM-128 recibido → guardar en cache (TTL 30s)
  ✗ Timeout/Error → compensar: revisar cache expirado (Soft Fail) o DENY (Hard Fail)

PASO 4: bhnexus evalúa políticas físicas
  → APB: consultar posición lógica en SBOSDB
  → 2PR: consultar ocupantes en SBOSDB
  → Mantrap: consultar ManTrapState en memoria
  ✓ Todas pasan → GRANT
  ✗ Alguna falla → DENY con reason específico

PASO 5: bhnexus → Puerta 1 → banexus
  payload: { type: "auth_response", outcome: "grant|deny",
             sam_128: { word_a, word_b }, actuator_commands: [...] }
  ✓ banexus ejecuta actuator_commands

COMPENSACIÓN TOTAL (si bhnexus no responde en 100ms):
  → banexus consulta Policy Cache local (AES-256-GCM, TTL 4h)
  → Si cache vigente: decidir localmente (fail-secure o permiso cached)
  → Si cache expirado: DENY (fail-secure obligatorio)
```

### 5.2 Saga de policy_push (bAuth → bhnexus → banexus)

```
EVENTO: cambio de RolTemplate en bAuth → evaluación CAEP

PASO 1: bAuth detecta cambio de política (INSERT/UPDATE en bos_rol_template)
  → bkernel WAL → Redis Stream 'sbos:events:nexus'

PASO 2: bAuth push via canal privilegiado (Sub-canal B)
  → PriviledgedSocketListener recibe PolicyUpdate { affected_nodes, sam_delta }

PASO 3: bhnexus invalida cache de nodos afectados
  → AuthCacheDecorator.invalidar_nodos(affected_nodes)
  → Log de invalidación con ctx_id

PASO 4: bhnexus propaga a banexus afectados
  → Por cada node_id en affected_nodes:
     Puerta 1 → { type: "policy_update", snapshot: <política cifrada AES-256-GCM> }

PASO 5: banexus persiste nuevo Policy Cache
  → Cifrar snapshot con clave HKDF-SHA256(private_key, node_id)
  → Escribir /var/lib/banexus/policy_cache.enc
  → Confirmar a bhnexus: { type: "policy_ack", node_id: "..." }

COMPENSACIÓN (si banexus no responde):
  → bhnexus reintenta en 30s, 60s, 120s
  → Si sigue sin responder → marcar nodo como stale → alerta Wazuh NEXUS-002
```

### 5.3 Saga de revocación de emergencia

```
EVENTO: incidente de seguridad → bAuth emite emergency_revoke

PASO 1: bAuth push via Sub-canal B
  → EventoPrivilegiadoBAuth::EmergencyRevoke { user_id, scope }

PASO 2: bhnexus purga cache inmediatamente
  → AuthCacheDecorator.purgar_usuario(user_id)
  → SAM-128 del usuario ya no existe en cache → próximo auth_request = cache miss

PASO 3: bhnexus activa DENY activo
  → Para requests en vuelo del mismo user_id: override a DENY
  → SAM-128 WORD-B bit revocado activo = 1

PASO 4: bhnexus notifica a banexus afectados
  → Puerta 1 → { type: "revocation_event", user_id, effective_immediately: true }
  → banexus elimina toda decisión cached del usuario
  → Si hay actuador abierto: trigger auto-close inmediato

COMPENSACIÓN (si canal B no está conectado):
  → bhnexus detecta ausencia de heartbeat de bAuth (>30s)
  → Alerta Wazuh NEXUS-007
  → Fail-secure: elevar restricciones (no conceder nuevos accesos hasta reconexión)
```

### 5.4 Saga de reconexión (banexus → bhnexus)

```
EVENTO: banexus pierde conexión Puerta 1 (red, restart bhnexus)

PASO R1: Detección de cierre (tokio-tungstenite onClose)
  → Estado → Reconectando

PASO R2: Backoff exponencial
  → Intento 1: 2s · Intento 2: 4s · Intento 3: 8s · ... máx 60s
  → Máximo 20 intentos → Estado → Error → alerta Wazuh NEXUS-001

PASO R3: Re-ejecutar handshake mTLS SPIFFE
  → Renovar SVID si TTL < 10min (SPIRE Agent automático)
  → Abrir WebSocket con nuevo SVID

PASO R4: Re-sincronizar estado
  → Enviar { type: "resync_request", last_known_seq: N }
  → bhnexus responde con eventos missed desde seq N
  → banexus actualiza Policy Cache si hay delta

MIENTRAS OFFLINE: banexus opera en modo offline
  → Policy Cache local (AES-256-GCM, TTL 4h)
  → Fail-secure al expirar
```

## 6. Normas y restricciones

| Norma | Restricción aplicada a bNexus |
|-------|-------------------------------|
| SBOS-050 P9 | NUNCA HTTP/TCP entre bhnexus y bAuth — solo Unix socket |
| ADR-020 | Interface Dual: `/run/bos/bhnexus.sock` expone WS-RPC + JSON-RPC 2.0 |
| RFC 6455 | WebSocket estándar en Puerta 1 — no protocolo propio |
| SBOS-049 | `ctx_id` obligatorio en toda operación — propagado en todos los frames |
| ISO 27001 A.8.20 | Toda llamada tiene audit trail en bos.audit_events via ctx_id |
| TLS 1.3 (rustls) | Puerta 1 usa únicamente rustls — sin OpenSSL, memory-safe |
| SPIFFE v1.0 | Autenticación mutua por SVID — no contraseñas entre daemons |
