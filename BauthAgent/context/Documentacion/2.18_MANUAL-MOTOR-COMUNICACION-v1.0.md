## 0. Principio rector

> **banexus-implicit es la forma universal. Cualquier app de software es un agente banexus-implicit.**  
> Flutter, Laravel, React, Vue, Django, Rails, FastAPI, Spring Boot — todos usan el mismo protocolo.  
> El Motor de Comunicación define ese protocolo una vez. Cada tecnología lo implementa.

Las aplicaciones no pasan por bhnexus. Se conectan **directamente a bAuth** mediante este motor.  
bhnexus es para hardware físico. Este motor es para todo lo demás.

*(Ref: `BnexusAgent/0.00_MANUAL-DIRECTRICES-NEXUS.md` §4)*

## 1. Los tres protocolos de banexus-implicit

banexus-implicit se define por tres protocolos RFC estándar soportados en cualquier lenguaje:

| Protocolo | Estándar | Responsabilidad | Soporte en ecosistemas |
|-----------|---------|----------------|----------------------|
| **mTLS X.509** | RFC 8446 | Prueba la identidad de la app ante bAuth | curl, Guzzle, requests, fetch, Dio, reqwest... |
| **JWT / OIDC** | RFC 6749 + 7519 | bAuth emite el token de sesión del usuario | laravel/passport, nuxt-auth, django-allauth... |
| **W3C Trace Context** | W3C + OTel | Propaga ctx_id en cada llamada | OTel SDK en 15+ lenguajes |

Estos tres protocolos son el contrato mínimo. Una app que los implementa es un cliente bAuth válido
sin importar el lenguaje, framework, o plataforma.

## 2. El transporte: WebSocket + JSON-RPC 2.0

### 2.1 Por qué WebSocket

| Alternativa | Por qué no |
|-------------|-----------|
| REST polling | No permite server push. Latencia de polling inaceptable para eventos CAEP. |
| gRPC | Requiere `.proto` por método. `grpc-web` necesita proxy. Sin ventaja sobre WS en browser. |
| SSE (Server-Sent Events) | Unidireccional — solo server push. No permite request/response correlacionado. |
| WebSocket + JSON-RPC 2.0 | Bidireccional. Multiplexado por `id`. RFC 6455. Nativo en browsers, VMs, CLIs. |

### 2.2 El protocolo de wire (resumen)

```
App                                    Kong → bAuth daemon
 │                                          │
 │── GET /ws HTTP/1.1 ────────────────────►│
 │   Upgrade: websocket                     │
 │   Authorization: Bearer <jwt>            │
 │   traceparent: 00-<trace-id>-<span>-01  │
 │◄─ 101 Switching Protocols ──────────────│
 │                                          │
 │── {"jsonrpc":"2.0",                     │
 │    "method":"bauth.rol_template.tree",  │
 │    "params":{"tenant":"skull"},         │
 │    "id":1}  ──────────────────────────►│
 │                                          │
 │◄─ {"jsonrpc":"2.0","result":{...},"id":1}
 │                                          │
 │   (canal abierto — múltiples requests   │
 │    en vuelo correlacionados por id)      │
```

Especificación completa de wire: `anexos/A.77_PROTOCOLO-WS-JSONRPC-v1.0.md`

### 2.3 URLs por entorno

| Entorno | URL | TLS | Auth |
|---------|-----|:---:|------|
| Desarrollo local | `ws://127.0.0.1:9450/ws` | No | JWT en header Upgrade |
| Staging | `ws://127.0.0.1:9450/ws` via Kong local | No (loopback) | JWT header Upgrade |
| Producción | `wss://bauth.sbos.local/ws` | TLS 1.3 | JWT header Upgrade + mTLS |

Solo la URL cambia entre entornos. El código de negocio no cambia.

## 3. El contrato de transporte — agnóstico de lenguaje

El contrato se expresa primero en pseudocódigo, luego se concreta por tecnología:

```
interfaz ITransporte {
  llamar(metodo: string, params: objeto) → Promise<objeto>
  conectar(uri: string, token: string)  → void
  desconectar()                         → void
  estaConectado()                       → bool
  onEvento(tipo: string, handler: fn)  → void  // para server push CAEP
}
```

Propiedades que toda implementación debe cumplir:
- **Multiplexado:** N requests en vuelo simultáneamente, correlacionados por `id` JSON-RPC
- **Reconexión automática:** backoff exponencial (2s → 4s → 8s → máx 60s) en desconexión
- **Renovación de token:** si JWT expira en < 5 min, renovar antes de la siguiente llamada
- **ctx_id propagado:** header `traceparent` en el Upgrade, heredado en cada request
- **Timeout por llamada:** 15s por defecto (configurable por método)

## 4. Implementaciones de referencia por tecnología

### 4.1 TypeScript — React / Vue / Node.js

```typescript
// sdk/bauth-client.ts — funciona en React, Vue, Angular, Node.js, Deno
// No hay dependencia de framework: solo la API WebSocket estándar (RFC 6455)

interface ITransporte {
  llamar(metodo: string, params?: Record<string, unknown>): Promise<unknown>;
  conectar(uri: string, token: string): Promise<void>;
  desconectar(): void;
}

class BauthWsTransporte implements ITransporte {
  private ws: WebSocket | null = null;
  private pendientes = new Map<number, {
    resolve: (v: unknown) => void;
    reject:  (e: Error) => void;
  }>();
  private nextId = 1;

  async conectar(uri: string, token: string): Promise<void> {
    this.ws = new WebSocket(uri, ['json-rpc-2.0']);
    // Workaround para enviar Bearer en Upgrade (browser no permite headers arbitrarios):
    // Kong acepta JWT como query param ?token=... en WebSocket upgrades
    this.ws = new WebSocket(`${uri}?token=${encodeURIComponent(token)}`, ['json-rpc-2.0']);
    await new Promise<void>((res, rej) => {
      this.ws!.onopen  = () => res();
      this.ws!.onerror = (e) => rej(new Error(`Conexión fallida: ${e}`));
    });
    this.ws.onmessage = (ev) => this.onFrame(ev.data as string);
    this.ws.onclose   = () => this.onCierre();
  }

  async llamar(metodo: string, params?: Record<string, unknown>): Promise<unknown> {
    const id = this.nextId++;
    return new Promise((resolve, reject) => {
      this.pendientes.set(id, { resolve, reject });
      this.ws!.send(JSON.stringify({ jsonrpc: '2.0', method: metodo, params, id }));
      setTimeout(() => {
        if (this.pendientes.has(id)) {
          this.pendientes.delete(id);
          reject(new Error(`Timeout en ${metodo}`));
        }
      }, 15_000);
    });
  }

  private onFrame(data: string) {
    const msg = JSON.parse(data);
    const cb  = this.pendientes.get(msg.id);
    if (!cb) return;
    this.pendientes.delete(msg.id);
    msg.error ? cb.reject(new Error(msg.error.message)) : cb.resolve(msg.result);
  }

  private onCierre() { /* disparar backoff exponencial — ver §5.2 */ }

  desconectar() { this.ws?.close(); }
}

// Uso en React / Vue (igual en ambos):
const cliente = new BauthWsTransporte();
await cliente.conectar('wss://bauth.sbos.local/ws', tokenJwt);
const arbol = await cliente.llamar('bauth.rol_template.tree', { tenant: 'skull' });
```

**Librerías OAuth2 recomendadas:**

| Framework | Librería de tokens | Observaciones |
|-----------|-------------------|---------------|
| React | `@auth0/auth0-react` o `oidc-client-ts` | bAuth = OIDC Provider estándar |
| Vue / Nuxt | `nuxt-auth-utils` o `oidc-client-ts` | Mismo, bAuth compatible OIDC |
| Node.js backend | `openid-client` (npm) | M2M con client_credentials |

### 4.2 PHP — Laravel / Symfony

```php
<?php
// app/Services/BauthTransporte.php
// Funciona en Laravel, Symfony, Slim, o PHP puro
// Usa WebSocket via Ratchet/Pawl o textalk/websocket-php

namespace App\Services;

use WebSocket\Client as WsClient;

class BauthTransporte
{
    private ?WsClient $ws = null;
    private int $nextId   = 1;

    public function conectar(string $uri, string $token): void
    {
        $this->ws = new WsClient($uri, [
            'headers' => [
                'Authorization' => "Bearer {$token}",
                'traceparent'   => request()->header('traceparent', $this->nuevoTraceparent()),
            ],
        ]);
    }

    public function llamar(string $metodo, array $params = []): mixed
    {
        $id = $this->nextId++;
        $this->ws->send(json_encode([
            'jsonrpc' => '2.0',
            'method'  => $metodo,
            'params'  => $params,
            'id'      => $id,
        ]));
        $resp = json_decode($this->ws->receive(), true);
        if (isset($resp['error'])) {
            throw new \RuntimeException($resp['error']['message'], $resp['error']['code']);
        }
        return $resp['result'];
    }

    private function nuevoTraceparent(): string
    {
        return sprintf('00-%s-%s-01', bin2hex(random_bytes(16)), bin2hex(random_bytes(8)));
    }
}
```

### 4.3 Dart — Flutter (desktop, mobile, web)

```dart
// lib/nucleo/comunicacion/bauth_transporte.dart
// Funciona en Flutter Desktop, Flutter Mobile, Flutter Web sin cambio de código

import 'dart:async';
import 'dart:convert';
import 'package:web_socket_channel/web_socket_channel.dart';

class BauthTransporte {
  WebSocketChannel? _canal;
  final _pendientes = <int, Completer<Map<String, dynamic>>>{};
  int _nextId = 1;

  Future<void> conectar(String uri, String token) async {
    final wsUri = Uri.parse(uri).replace(
      queryParameters: {'token': token},  // Kong acepta JWT en query param
    );
    _canal = WebSocketChannel.connect(wsUri, protocols: const ['json-rpc-2.0']);
    await _canal!.ready;
    _canal!.stream.listen(_onFrame, onDone: _onCierre);
  }

  Future<Map<String, dynamic>> llamar(
    String metodo, [Map<String, dynamic>? params]) {
    final id = _nextId++;
    _canal!.sink.add(jsonEncode({'jsonrpc':'2.0','method':metodo,'params':params,'id':id}));
    final c = Completer<Map<String, dynamic>>();
    _pendientes[id] = c;
    return c.future.timeout(
      const Duration(seconds: 15),
      onTimeout: () => throw TimeoutException('Timeout en $metodo'),
    );
  }

  void _onFrame(dynamic data) {
    final msg = jsonDecode(data as String) as Map<String, dynamic>;
    final cb  = _pendientes.remove(msg['id'] as int?);
    if (cb == null) return;
    final err = msg['error'];
    err != null
      ? cb.completeError(RpcError(err['code'] as int, err['message'] as String))
      : cb.complete((msg['result'] as Map<String, dynamic>?) ?? {});
  }

  void _onCierre() { /* disparar backoff exponencial — §5.2 */ }
  void desconectar() => _canal?.sink.close();
}
```

**Librería OAuth2:** `flutter_appauth` (PKCE, OIDC discovery) o `dart_jsonwebtoken` para validación local.

### 4.4 Rust — daemons M2M (biedata, bnotify, bsearch → bAuth)

```rust
// src/transport/bauth_cliente.rs
// Para daemons hermanos que llaman a bAuth sin usuario interactivo (M2M).
// Autenticación: client_credentials + mTLS de daemon.

use tokio_tungstenite::{connect_async_tls_with_config, tungstenite::Message};
use tokio_tungstenite::tungstenite::client::IntoClientRequest;
use serde_json::{json, Value};
use std::sync::atomic::{AtomicU32, Ordering};
use std::sync::Arc;

pub struct BauthCliente {
    uri:    String,
    token:  String,           // M2M token renovado via client_credentials
    next_id: Arc<AtomicU32>,
}

impl BauthCliente {
    pub async fn llamar(&self, metodo: &str, params: Value, ctx_id: &str) -> anyhow::Result<Value> {
        let id = self.next_id.fetch_add(1, Ordering::SeqCst);
        let mut req = self.uri.as_str().into_client_request()?;
        req.headers_mut().insert(
            "Authorization",
            format!("Bearer {}", self.token).parse()?,
        );
        req.headers_mut().insert("traceparent", ctx_id.parse()?);

        let (mut ws, _) = connect_async_tls_with_config(req, None, false, None).await?;
        let payload = json!({"jsonrpc":"2.0","method":metodo,"params":params,"id":id});
        ws.send(Message::Text(payload.to_string())).await?;

        if let Some(Ok(Message::Text(resp))) = ws.next().await {
            let msg: Value = serde_json::from_str(&resp)?;
            if let Some(err) = msg.get("error") {
                anyhow::bail!("Error bAuth: {}", err["message"]);
            }
            Ok(msg["result"].clone())
        } else {
            anyhow::bail!("Respuesta inesperada de bAuth")
        }
    }
}
```

**Nota:** los daemons Rust usan Unix socket para comunicación interna (SBOS-050 P9), pero
pueden usar WebSocket TLS al conectar a bAuth como clientes externos con token M2M.

### 4.5 Python — Django / FastAPI

```python
# bauth/transporte.py — agnóstico de framework (Django, FastAPI, Flask)
import asyncio, json, uuid
from websockets import connect as ws_connect

class BauthTransporte:
    def __init__(self, uri: str, token: str):
        self._uri   = uri
        self._token = token
        self._ws    = None
        self._next_id = 1

    async def conectar(self):
        headers = {
            "Authorization": f"Bearer {self._token}",
            "traceparent":   f"00-{uuid.uuid4().hex}-{uuid.uuid4().hex[:16]}-01",
        }
        self._ws = await ws_connect(self._uri, additional_headers=headers,
                                     subprotocols=["json-rpc-2.0"])

    async def llamar(self, metodo: str, params: dict | None = None) -> dict:
        id_ = self._next_id; self._next_id += 1
        await self._ws.send(json.dumps({"jsonrpc":"2.0","method":metodo,"params":params,"id":id_}))
        resp = json.loads(await asyncio.wait_for(self._ws.recv(), timeout=15))
        if "error" in resp:
            raise RuntimeError(f"bAuth error: {resp['error']['message']}")
        return resp.get("result", {})

    async def desconectar(self):
        if self._ws: await self._ws.close()
```

**Librería OAuth2:** `authlib` (Django/FastAPI) con OIDC discovery apuntando a bAuth.

## 5. Sagas del motor de comunicación

Las sagas son agnósticas de lenguaje — el flujo es idéntico en todas las tecnologías.
La especificación detallada está en `anexos/A.78_SAGAS-MOTOR-COMUNICACION-v1.0.md`.

### 5.1 Saga de conexión

```
PASO 1: Obtener token válido
  → IRepositorioTokens.tokenValido() / AuthProvider.getToken()
  → Si no hay token: flujo OIDC/PKCE → bAuth emite JWT
  ✓ Token vigente con exp > now + 5min

PASO 2: Abrir WebSocket con token
  → WebSocket(uri + "?token=<jwt>") — o header Authorization en Upgrade (si disponible)
  → Esperar handshake HTTP Upgrade (101 Switching Protocols)
  ✓ Canal abierto
  ✗ 401 → token inválido → compensar: invalidar token + ir a PASO 1
  ✗ 503 → bAuth no disponible → compensar: backoff exponencial

PASO 3: Verificar canal
  → llamar("bauth.health.check", {}) → { status: "operativo", version: "3.x" }
  ✓ Canal activo
  ✗ Timeout 5s → compensar: cerrar + ir a PASO 2

RESULTADO: canal listo para operación
```

### 5.2 Saga de reconexión

```
EVENTO: WebSocket cerrado inesperadamente (red, restart bAuth, Kong reset)

PASO R1: Detectar cierre
  → onclose / onDone / onError del canal

PASO R2: Backoff exponencial
  → 2s → 4s → 8s → 16s → 32s → máx 60s
  → Máximo 10 intentos → emitir error → notificar UI ("Sin conexión")

PASO R3: Re-ejecutar Saga de conexión completa
  → Si token expiró durante el intento: renovar primero

COMPENSACIÓN TOTAL (10 intentos fallidos):
  → Invalidar sesión local
  → Mostrar pantalla de login (apps interactivas) o alertar (daemons M2M)
```

### 5.3 Saga de renovación de token

```
EVENTO: exp del JWT < now + 5min (detectado antes de cada llamada)

PASO T1: Renovar via refresh_token
  → POST bauth.session.refresh { refresh_token: <rt> }
  ← { token: <nuevo_jwt>, refresh_token: <nuevo_rt>, expira_en: <epoch> }

PASO T2: Persistir nuevo token
  → SecureStorage / flutter_secure_storage / Laravel cache cifrado

PASO T3: Reconectar WebSocket con nuevo token
  → Cerrar canal actual
  → Abrir canal con nuevo token

COMPENSACIÓN (refresh_token expirado):
  → Limpiar tokens
  → Flujo OIDC/PKCE completo
```

### 5.4 Saga de revocación (logout / incidente CAEP)

```
EVENTO: usuario hace logout, o bAuth emite evento CAEP session_ended

PASO V1: Invalidar en servidor
  → llamar("bauth.session.logout", { jti: <jti_del_token_activo> })
  ← { ok: true }

PASO V2: Limpiar estado local
  → Borrar tokens del storage seguro
  → Cerrar WebSocket

PASO V3: Navegar a login (apps) / detener daemon M2M

COMPENSACIÓN (sin conexión al hacer logout):
  → Limpiar local de todos modos
  → El JWT expira en bAuth cuando caduca (máx 8h)
```

## 6. Normas irrenunciables

| Norma | Restricción |
|-------|------------|
| SBOS-050 P9 | NUNCA HTTP/TCP directo entre daemons hermanos — solo Unix socket |
| ADR-020 | Interface Dual: /run/bos/bauth.sock para daemons; TCP 9450 para clientes externos vía Kong |
| RFC 6455 | WebSocket estándar — no protocolos propios |
| RFC 9110 | `Authorization: Bearer <jwt>` o `?token=<jwt>` en Upgrade — según soporte de la plataforma |
| NIST SP 800-63B | Canal TLS 1.3 obligatorio en producción |
| SBOS-049 | `traceparent` inyectado en cada conexión — ctx_id se propaga por toda la operación |
| ISO 27001 A.8.20 | Todo canal de comunicación auditado — ctx_id presente en toda respuesta bAuth |
