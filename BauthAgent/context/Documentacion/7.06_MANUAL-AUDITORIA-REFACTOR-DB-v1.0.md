# 7.06 — Manual de Auditoría y Refactorización DB · bAuth

**Versión:** 1.0.0 · **Fecha:** 2026-08-02 · **Estado:** Activo

---

## Idea central

El código Rust de bAuth fue escrito cuando la base de datos tenía nombres legacy inconsistentes.
La BD fue corregida (DDL v2.12.0, 158 tablas canónicas en SBOSDB). El código **no** fue
actualizado: contiene **36 tablas phantom** (no existen en el DDL actual) con **~250 referencias
SQL** dispersas en 64 archivos.

**El objetivo:** que cada `FROM`, `INTO`, `UPDATE` y `JOIN` en el código apunte a una tabla
real de SBOSDB, y que los structs Rust reflejen las columnas actuales del DDL.

**Fuente de verdad:** `DDLs/SBOS_db_V2_DDL.sql` — inmutable durante el refactor.  
**Referencia de nombres:** `context/Documentacion/anexos/A.74` — mapa legacy → canónico.

## Reglas del refactor

1. **DDL es inmutable** — el código se adapta al DDL, nunca al revés.
2. **Una capa a la vez** — `cargo check` verde antes de pasar a la siguiente.
3. **Sin lógica nueva** — solo renombrar tablas/columnas y ajustar structs. El comportamiento no cambia.
4. **Cada tabla con decisión documentada** — si no hay equivalente claro en el DDL, se escala al humano antes de codificar.
5. **SBOSDB es el árbitro** — si una query corregida falla en la VPS, retrocedemos.
