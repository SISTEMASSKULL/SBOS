## 1. Audiencia, propósito y alcance

El Motor de Roles es la **capa de gestión programática** de roles en bAuth. No es solo
consulta — es CRUD completo, asignación, revocación, consulta de relaciones, y auditoría.
Funciona vía JSON-RPC 2.0 sobre el Unix socket `/run/bos/bauth.sock` (ADR-020) y vía
CLI (`bauthctl`). No requiere el dashboard. Cualquier sistema externo (ERP, RRHH, CI/CD)
puede gestionar roles mediante la API.

**El Motor de Roles NO es atomc.** atomc compila el árbol fuente y emite el IR. El Motor
de Roles gestiona roles, átomos, asignaciones y sus relaciones en runtime.

**Audiencia:** desarrolladores de integraciones, administradores de sistemas, pipelines CI/CD.

|---|---|---|---|

| **Azure AD** | `New-AzureADDirectoryRole`, `Add-AzureADDirectoryRoleMember` | `AzureAD` PowerShell | CRUD de roles, membresía, PIM |

Todas las plataformas IAM exponen gestión de roles vía API. El dashboard es opcional.
La API es el contrato. bAuth sigue el mismo patrón.

## 4. API JSON-RPC completa

### 4.1 CRUD de roles

```
bauth.rol.create(template_json)
  → Crea un nuevo rol desde un template
  → Valida contra idn_rolestpl_requisito
  → Retorna { role_id, status }

bauth.rol.update(role_id, cambios)
  → Actualiza atributos del rol
  → Registra cambio en idn_rolestpl_atom_history

bauth.rol.delete(role_id)
  → Soft-delete: status → ARCHIVED
  → Verifica que ningún usuario tenga este rol activo

bauth.rol.archive(role_id)
  → Archivo definitivo (inmutable)
  → Solo si status = DEPRECATED por > 90 días

bauth.rol.list(tenant_id, filters?)
  → Lista roles del tenant
  → Filtros: tier, status, dominio, conjunto (D98)
```

### 4.2 Asignación átomo ↔ rol

```
bauth.rol.atom.assign(role_id, atom_code, allowed=true)
  → INSERT en privilege_role_atom
  → compute_rol_bitmask() → recalcula RolBitMask
  → Registra en idn_rolestpl_atom_history

bauth.rol.atom.revoke(role_id, atom_code)
  → allowed = false en privilege_role_atom
  → Recalcula RolBitMask

bauth.rol.atom.list(role_id)
  → Todos los átomos del rol, agrupados por dominio
  → [{ domain: "D1", atoms: [...], count: 47 },
     { domain: "D3", atoms: [...], count: 12 }]

bauth.rol.atom.filter(role_id, dominio="D3")
  → Solo átomos del dominio D3 (Financiero)
```

### 4.3 Consulta de relaciones rol ↔ usuario

```
bauth.rol.user.assign(role_id, user_uuid, mode="PERMANENTE", valid_until?)
  → INSERT en idn_user_role
  → Pasa validación SoD
  → compute_user_bitmask() → recalcula UserBitMask

bauth.rol.user.revoke(role_id, user_uuid)
  → is_active = false, revoked_by = actor
  → Recalcula UserBitMask

bauth.rol.user.list(role_id)
  → Usuarios que tienen este rol asignado
  → [{ user_uuid, username, mode, valid_from, valid_until }]

bauth.rol.user.count(role_id)
  → 47 usuarios activos con este rol
```

### 4.4 Consulta de relaciones usuario → roles

```
bauth.usuario.rol.list(user_uuid)
  → Todos los roles del usuario (activos y temporales)
  → [{ role_id, role_name, mode, valid_from, valid_until, is_active }]

bauth.usuario.rol.activos(user_uuid)
  → Solo roles activos (no revocados, no expirados)
```

### 4.5 Consulta de conjuntos (D98)

```
bauth.grupo.rol.list(set_slug)
  → Roles miembros del conjunto
  → ["analista_pagos", "contador_junior"]

bauth.grupo.atom.list(set_slug)
  → Unión de átomos de todos los roles del conjunto

bauth.grupo.user.list(set_slug)
  → Usuarios que tienen al menos un rol del conjunto
```

### 4.6 Consulta de átomo → roles

```
bauth.atom.rol.list(atom_slug)
  → Qué roles tienen este átomo asignado
  → [{ role_id, role_name, allowed, tier }]

bauth.atom.user.list(atom_slug)
  → Qué usuarios (vía sus roles) tienen este átomo
  → Resuelve: átomo → role_atom → user_role → user
```

### 4.7 Auditoría y comparación

```
bauth.rol.history(role_id)
  → Historial de cambios del rol
  → [{ changed_at, change_type, old_state, new_state, changed_by }]

bauth.rol.compare(role_id_a, role_id_b)
  → Diferencia entre dos roles
  → { comunes: 23, solo_a: 15, solo_b: 8, conflicto_sod: 2 }
```

## 5. Acceso vía CLI (bauthctl)

```bash
# CRUD
bauthctl rol create --template vendedor_senior.json
bauthctl rol update cajero --tier BIZ_N1 --status ACTIVE
bauthctl rol delete cajero
bauthctl rol list --tenant t-skull --tier BIZ_N1

# Asignación átomo ↔ rol
bauthctl rol atom assign cajero d1.zona_ventas.venta_lectura
bauthctl rol atom revoke cajero d3.payment.approve
bauthctl rol atom list cajero
bauthctl rol atom filter cajero --dominio D3

# Asignación rol ↔ usuario
bauthctl rol user assign cajero jperez --mode TEMPORAL --until 2024-12-31
bauthctl rol user revoke cajero jperez
bauthctl rol user list cajero

# Consulta
bauthctl usuario rol list jperez
bauthctl grupo rol list financieros_tier2
bauthctl atom rol list d1.zona_ventas.approve

# Auditoría
bauthctl rol history cajero
bauthctl rol compare cajero vendedor_senior
```

## 6. Pipeline completo: 4 motores

| Motor | Opera sobre | ¿Lee o escribe? | Verbos / API | Consumidores |
|---|---|---|---|---|
| **Motor de Identidad** | idn_identidad_* | Lee y escribe | validate, verify, format, CRUD | Dashboard, CLI, ERP |
| **atomc** | privilege_atom, .atm.yaml | Lee y escribe | validate, compose, resolve, compile | Dashboard, CLI, CI/CD |
| **Motor de Roles** | privilege_atom, privilege_role_atom, idn_user_role, idn_role_template | **Lee y escribe** | CRUD, assign, revoke, list, filter, compare, history | Dashboard, CLI, ERP, RRHH, CI/CD |
| **BitMask** | UserBitMask | Solo LEE | evaluate (<0.5ns) | Kong PEP, todos los daemons |

## 7. Tablas que el Motor de Roles gestiona

| Tabla | Operación | Motor de Roles |
|---|---|---|
| `idn_role_template` | INSERT, UPDATE, DELETE (soft) | `rol.create()`, `rol.update()`, `rol.delete()` |
| `privilege_role_atom` | INSERT, UPDATE (allowed=false) | `rol.atom.assign()`, `rol.atom.revoke()` |
| `idn_user_role` | INSERT, UPDATE (is_active=false) | `rol.user.assign()`, `rol.user.revoke()` |
| `idn_role_closure` | SELECT | `rol.list()`, `grupo.rol.list()` |
| `privilege_atom` | SELECT | `rol.atom.list()`, `atom.rol.list()` |
| `idn_rolestpl_atom_history` | INSERT | Cada cambio de asignación |
