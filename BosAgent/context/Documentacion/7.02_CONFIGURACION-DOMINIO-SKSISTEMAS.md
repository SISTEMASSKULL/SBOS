### 1.2 Registros PENDIENTES — agregar en GcomHosting

> Estos registros **no existen todavía** y son necesarios para que el correo funcione.

#### MX — recepción de correo

```
Tipo:  MX
Nombre: @ (raíz del dominio)
Valor:  mail.sksistemas.com
Prioridad: 10
```

#### TXT — SPF (evita que el correo llegue como spam)

```
Tipo:  TXT
Nombre: @ (raíz del dominio)
Valor:  v=spf1 a mx ip4:13.140.128.230 ~all
```

#### TXT — DMARC (política de autenticación de correo)

```
Tipo:  TXT
Nombre: _dmarc
Valor:  v=DMARC1; p=quarantine; rua=mailto:admin@sksistemas.com
```

### 1.4 DKIM — configurar después de instalar mailserver

El DKIM lo genera automáticamente la ficha `mailserver` al instalarse.
BOS escribe el valor de la clave pública en el log de instalación.

Después de instalar mailserver, agregar en GcomHosting:

```
Tipo:  TXT
Nombre: mail._domainkey
Valor:  [BOS lo genera — ver log de ficha mailserver]
```

## 2. Arquitectura nginx ↔ subdominios

### 2.1 Flujo de una petición

```
Usuario → sksistemas.com (o cualquier subdominio)
         │
         ▼ 13.140.128.230
    nginx HOST (SSL termination)
         │
         ├─ desktop.sksistemas.com ──────→ oauth2-proxy-desktop (WebSocket directo)
         │
         ├─ sksistemas.com                \
         ├─ www.sksistemas.com             ├─→ bcms / placeholder institucional
         │                                /
         │
         └─ TODOS los demás subdominios ──→ Kong API Gateway
                                                   │
                                    ┌──────────────┼──────────────┐
                                    ▼              ▼              ▼
                               Keycloak       Nextcloud        Vault
                             (auth.*)      (documents.*)   (vault.*)
                                ...             ...            ...
```

### 2.2 Archivos generados por la ficha nginx

La ficha nginx genera automáticamente un archivo por subdominio en:
```
/etc/nginx/conf.d/domains/
├── sbos-institucional.conf   ← sksistemas.com + www
├── sbos-auth.conf            ← auth.sksistemas.com → Kong
├── sbos-mail.conf            ← mail.sksistemas.com → Kong
├── sbos-desktop.conf         ← desktop.sksistemas.com → oauth2-proxy (WebSocket)
├── sbos-vault.conf           ← vault.sksistemas.com → Kong
├── sbos-secrets.conf         ← secrets.sksistemas.com → Kong
├── sbos-api.conf             ← api.sksistemas.com → Kong
├── sbos-gateway.conf         ← gateway.sksistemas.com → Kong
├── sbos-documents.conf       ← documents.sksistemas.com → Kong
├── sbos-sign.conf            ← sign.sksistemas.com → Kong
├── sbos-find.conf            ← find.sksistemas.com → Kong
├── sbos-reports.conf         ← reports.sksistemas.com → Kong
├── sbos-devops.conf          ← devops.sksistemas.com → Kong
├── sbos-queues.conf          ← queues.sksistemas.com → Kong
├── ...                       ← (30 archivos en total)
└── tenant-*.conf             ← bcms escribe aquí (prefijo diferente)
```

### 2.3 Integración bcms (S16-webserver)

bcms gestiona dominios de tenants. El protocolo es:

1. bcms escribe `/etc/nginx/conf.d/domains/tenant-<empresa>.conf`
2. bcms llama `nginx -s reload` (sin downtime)
3. nginx sirve el dominio del tenant inmediatamente

**Convención de nombres:**
- `sbos-*.conf` → servicios SBOS (gestionados por ficha nginx)
- `tenant-*.conf` → dominios de tenants (gestionados por bcms)

Total: **33 dominios** en un solo certificado (límite Let's Encrypt: 100).

### 3.2 Pasos para activar el certificado real

```bash
# 1. Instalar nginx (debe estar activo para HTTP-01 challenge)
bosctl ficha install nginx

# 2. Instalar certbot (solicita cert staging primero, luego prod)
bosctl ficha install certbot

# 3. Cuando el staging sea exitoso, obtener cert de producción:
#    (certbot lo hace automáticamente al detectar staging OK)
certbot certonly --webroot -w /var/www/certbot \
    -d sksistemas.com -d www.sksistemas.com \
    -d auth.sksistemas.com -d mail.sksistemas.com \
    [... todos los -d del SBOS_SUBDOMAIN_LIST ...]
    --email admin@sksistemas.com --agree-tos

# 4. Reparar nginx para que use el nuevo cert Let's Encrypt
bosctl ficha repair nginx
```

### 3.3 Renovación automática

La ficha certbot configura un **systemd timer** que renueva cada semana:
```
certbot-renew.timer   → certbot-renew.service   → sbos-certbot-renew.sh
```
