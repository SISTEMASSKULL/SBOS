## 1. Por qué existe el Event Bus

Las fichas y los daemons del SBOS necesitan comunicarse entre sí cuando ocurren eventos
de ciclo de vida. Sin un event bus, cada daemon tendría que polling al daemon BOS para
saber si una ficha cambió de estado — lo que viola el principio de separación de responsabilidades.

**Con el Event Bus Redis Streams:**
- BOS publica eventos → los daemons suscritos reaccionan en tiempo real
- bAuth sabe cuándo una ficha de identidad fue reparada → invalida caches afectados
- bkernel sabe cuándo PG fue actualizado → reinicia su listener CDC
- El Context Plane sabe cuándo un evento de ctx ocurrió → propaga a bAuth

---

## 2. Arquitectura — Redis Streams DB0

Redis Streams es la tecnología de elección porque:
- Ya está en el stack SBOS (DB0 = streams)
- Garantías `at-least-once` con Consumer Groups
- Persistencia configurable (AOF)
- Latencia < 1ms en el mismo cluster K8s

```
┌─────────────────────────────────────────────────────────────────────┐
│                      Redis DB0 — Streams                             │
│                                                                       │
│  bos:events:ficha    ← BOS lifecycle (install/uninstall/degraded)   │
│  bos:events:ctx      ← Context Plane (promoted/invalidated/switch)  │
│  bos:events:capacity ← Capacity (warn/crit/scale)                   │
│  bos:events:tenant   ← Tenant lifecycle (create/suspend/remove)     │
└─────────────────────────────────────────────────────────────────────┘
         ▲ Publisher                    ▼ Consumers
    BOS daemon                    bAuth, bkernel, biedata, bsearch
    Context Plane                 Wazuh SIEM (via Filebeat)
    Capacity Engine               Alertmanager
```

## 3. Streams y eventos

### 3.1 `bos:events:ficha` — Ciclo de vida de fichas

Publicado por `internal/ficha/lifecycle.go` en cada transición de estado.

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `event_type` | string | `ficha.installed` \| `ficha.uninstalled` \| `ficha.degraded` \| `ficha.repaired` \| `ficha.paused` \| `ficha.error` |
| `ficha_id` | string | Identificador único de la ficha |
| `ficha_name` | string | Nombre legible (`postgresql`, `bauth`, etc.) |
| `server` | string | Servidor lógico (`S01-dataserver`, `S03-identityserver`) |
| `state_from` | string | Estado anterior (INSTALLED, READY, etc.) |
| `state_to` | string | Nuevo estado |
| `tenant_id` | string | Tenant afectado (`skull` para fichas globales) |
| `ctx_id` | string | ctx_id de la operación que causó el evento |
| `ts` | string | ISO 8601 timestamp |

**Ejemplo:**
```json
{
  "event_type": "ficha.degraded",
  "ficha_id": "fch-postgresql-s01",
  "ficha_name": "postgresql",
  "server": "S01-dataserver",
  "state_from": "INSTALLED",
  "state_to": "DEGRADED",
  "tenant_id": "skull",
  "ctx_id": "01923ac7-4f22-7a3b-b6e1-2c3d4e5f6a7b",
  "ts": "2026-07-31T14:32:01.123Z"
}
```

### 3.2 `bos:events:ctx` — Ciclo de vida del Context Plane

Publicado por `internal/context/service.go`.

| `event_type` | Cuándo | Qué hace el consumer |
|-------------|--------|---------------------|
| `ctx.promoted` | device registrado → sesión activa | bAuth: crear sesión en su cache |
| `ctx.invalidated` | sesión terminada (logout, TTL, admin) | bAuth: invalidar caches relacionados |
| `ctx.switch` | cambio de empresa/sucursal dentro de sesión | bAuth: re-evaluar 12 dominios |
| `ctx.step_up` | LoA aumentó (autenticación adicional) | bAuth: actualizar LoA en cache |

### 3.3 `bos:events:capacity` — Alertas de capacidad

Publicado por `internal/capacity/action_engine.go`.

| `event_type` | Severidad | Consumers |
|-------------|-----------|-----------|
| `capacity.warn` | MEDIUM | Wazuh SIEM, Alertmanager |
| `capacity.critical` | HIGH | Wazuh SIEM, Alertmanager, PagerDuty |
| `capacity.scale_up` | INFO | bAuth (ajusta rate limits), biedata |
| `capacity.block_admission` | HIGH | Kong (vía bos.ctx.validate 503) |

### 3.4 `bos:events:tenant` — Ciclo de vida de tenants

Publicado por `internal/installer/tenant.go`.

| `event_type` | Consumers |
|-------------|-----------|
| `tenant.created` | bAuth (crea realm KC + identidades base) · bkernel (subscribe nuevo schema) |
| `tenant.suspended` | bAuth (suspende realm) · Context Plane (invalida ctx_id del tenant) |
| `tenant.removed` | bAuth (elimina realm) · bkernel · bsearch (elimina índices) |

## 4. API del paquete `internal/eventbus/`

```go
// publisher.go
type Publisher interface {
    Publish(ctx context.Context, stream string, event Event) (id string, err error)
    PublishFicha(ctx context.Context, evt FichaEvent) error
    PublishCtx(ctx context.Context, evt CtxEvent) error
    PublishCapacity(ctx context.Context, evt CapacityEvent) error
    PublishTenant(ctx context.Context, evt TenantEvent) error
}

// subscriber.go — Consumer Groups (at-least-once)
type Subscriber interface {
    Subscribe(ctx context.Context, stream, group, consumer string,
              handler func(Event) error) error
    Ack(ctx context.Context, stream, group string, ids ...string) error
}
```

**Consumer Groups:** cada daemon que consume del event bus tiene su propio Consumer Group.
Si bAuth está caído, sus mensajes se acumulan en el stream (hasta max 10K mensajes o 24h).
Cuando bAuth se recupera, procesa los mensajes pendientes en orden.

## 5. Integración con lifecycle.go

```go
// internal/ficha/lifecycle.go — al completar transición de estado
func (l *Lifecycle) publishStateEvent(ctx context.Context,
    ficha *Ficha, from, to FichaState) {
    _ = l.eventbus.PublishFicha(ctx, FichaEvent{
        EventType: stateToEventType(to),  // "ficha.installed", "ficha.degraded", etc.
        FichaID:   ficha.ID,
        FichaName: ficha.Name,
        Server:    ficha.Server,
        StateFrom: string(from),
        StateTo:   string(to),
        TenantID:  ficha.TenantID,
        CtxID:     bosctx.FromContext(ctx),
        Ts:        time.Now().UTC().Format(time.RFC3339Nano),
    })
    // fire-and-forget: el error de publicación no debe fallar la transición de estado
}
```

## 6. Contratos con daemons consumidores

| Daemon | Stream | Consumer Group | Acción esperada |
|--------|--------|----------------|----------------|
| bAuth | `bos:events:ficha` | `bauth-ficha` | Si `ficha.degraded` en ficha de identidad → invalidar cache de evaluación de dominios |
| bAuth | `bos:events:ctx` | `bauth-ctx` | `ctx.promoted` → registrar sesión · `ctx.invalidated` → limpiar |
| bAuth | `bos:events:tenant` | `bauth-tenant` | `tenant.created` → bootstrap identidades base en bAuth |
| bkernel | `bos:events:ficha` | `bkernel-ficha` | `ficha.installed` para PG → iniciar listener CDC |
| bkernel | `bos:events:tenant` | `bkernel-tenant` | `tenant.created` → suscribir nuevo schema en WAL |
| biedata | `bos:events:capacity` | `biedata-cap` | `capacity.block_admission` → reducir rate de ingesta |
| Wazuh | `bos:events:capacity` | `wazuh-cap` | Todo evento → correlacionar con reglas SBOS-001..SBOS-007 |

## 7. Retención y monitoreo

```bash
# Ver mensajes pendientes en stream
redis-cli -n 0 XLEN bos:events:ficha          # total mensajes
redis-cli -n 0 XPENDING bos:events:ficha bauth-ficha - + 10   # pendientes para bAuth

# Configurar retención (MAXLEN ~) — mantener últimos 10K mensajes
redis-cli -n 0 XTRIM bos:events:ficha MAXLEN ~ 10000
```

Prometheus gauge: `bos_eventbus_stream_len{stream="bos:events:ficha"}` — alerta si > 5000 (consumer caído).
