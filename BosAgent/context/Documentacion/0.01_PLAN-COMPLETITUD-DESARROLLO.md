## Lectura obligatoria antes de usar este plan

Este plan NO es un backlog de tareas. Es un **mapa de madurez** estructurado según los
6 motores del corpus documental. El orden de los motores define el orden del desarrollo:
no se puede observar lo que no está instalado (① antes que ②), no se puede administrar fichas
sin observabilidad (② antes que ③), no se puede resolver contexto sin fichas instaladas
(③ antes que ④), no se puede certificar sin contexto (④ antes que ⑤-⑥).

**El norte es IAM Enterprise.** Eso significa: FAPI 2.0, NIST SP 800-207 Zero Trust,
ISO 27001:2022 A.8.x, OAuth 2.1, OIDC, SCIM, mTLS, SLOs verificados.
Cada fase de este plan avanza hacia ese estándar.

**Principio de verificación:** una fase está completa cuando el operador puede ejecutar
los comandos de verificación en la VPS y obtener el resultado esperado — sin leer el código.

**Norte industria (A.01):** el BOS es la única plataforma de 3ra generación: combina
zero-touch bootstrap del SO (que Terraform/Crossplane no hacen), reconciliación continua
(que Terraform no hace), sagas con compensación (que ninguno hace), Context Plane (único),
y soberanía total. Los estándares de A.09 son el piso mínimo, no el techo.

## Raíz de producción: `/opt/skull/SBOS/` (A.02)

El BOS materializa esta raíz en `bosctl system-install`. **Todo** — binarios, config,
runtime, logs, estado, datos, backups — vive aquí. Lo que antes estaba en rutas dispersas
(`/etc/bos/`, `/run/bos/`, `/var/log/bos/`) son **symlinks** que apuntan a subdirectorios
de esta raíz.

```
/opt/skull/SBOS/
├── bin/          ← binarios de todos los daemons y el CLI
├── core/         ← 5 scripts del motor Bash
├── blibs/        ← caché del catálogo de fichas
├── servers/      ← shared kernel — fuente única de fichas
├── DDLs/         ← shared kernel — fuente única de DDLs
├── config/       ← bos.toml, .env, rbac/, tls/
├── runtime/      ← bos.sock, bos.pid (efímero)
├── logs/         ← bos.log, audit.log, fichas/
├── state/        ← .sbos_state.json (fcntl.flock)
├── data/         ← PVs de K8s (bind mount desde /data/)
├── backups/      ← pg_dump, vault snapshots, state backups
├── kube/         ← kubeconfig
├── tenant/       ← tenant.conf
└── paths.yml     ← rutas canónicas (sin hardcode en código)
```

Symlinks de compatibilidad (creados por bos-preflight):
```
/etc/bos/   → /opt/skull/SBOS/config/
/run/bos/   → /opt/skull/SBOS/runtime/
/var/log/bos/ → /opt/skull/SBOS/logs/
/var/lib/bos/ → /opt/skull/SBOS/state/
```

## FASE II — Seguridad Zero Trust

**Motor:** ① IAM Installer (1.04 NRS) · **Manuales:** 1.04 · 1.05 · A.09 · A.15 (parcial)
**Estándar IAM Enterprise:** NIST SP 800-207 · ISO 27001 A.8.22 · CIS K8s v8 · NSA/CISA K8s Hardening · NRS-01..NRS-12
**Requiere:** Fase I completa (Vault PKI operativo)

### Por qué segundo

El A.09 define 7 principios de Zero Trust (NIST 800-207) que el BOS debe cumplir todos.
El Tenet 1 (todo recurso accesible solo vía PEP = Kong) y el Tenet 5 (monitoreo continuo)
requieren NetworkPolicy deny-all y Wazuh respectivamente — ambos son "❌ sin implementar"
en el manual 1.04. Sin mTLS entre daemons (NRS-03), el Context Plane no puede satisfacer
ISO 27001 A.8.5 (autenticación segura).
