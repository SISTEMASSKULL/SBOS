## 1. Qué es una saga y por qué es obligatoria

Una saga es una secuencia de pasos con **compensación automática**. Si el paso N falla, los
pasos 1 a N-1 se revierten en orden inverso. El sistema nunca queda en estado inconsistente.

### 1.1 Fundamento normativo

Las sagas son obligatorias por tres marcos:

- **OTel CNCF:** toda operación multi-servicio debe tener trace context propagado. La saga
  del BOS genera `traceparent` en cada paso para trazabilidad completa.
- **SRE (Site Reliability Engineering):** toda operación de infraestructura debe ser
  idempotente y reversible. La saga garantiza ambas.
- **ITIL 4 — Change Enablement:** todo cambio que afecte servicios debe tener plan de
  rollback validado. La compensación ES el plan de rollback.

### 1.2 Patrón: Saga Engine

El `SagaEngine` en `internal/installer/saga.go` implementa el patrón de orquestación:
- **DAG con oleadas paralelas:** los pasos sin dependencia entre sí se ejecutan en paralelo
- **Compensación inversa:** si el paso N falla, se compensan N-1, N-2... en orden inverso
- **Persistencia:** el estado de la saga se guarda tras cada paso. Si el daemon se reinicia,
  `Recuperar()` restaura el estado y continúa desde donde quedó.

## 2. La saga de 7 pasos — `bosctl deploy seed.yml`

| Paso | Acción | Ficha | Timeout | Compensación | SLO |
|:----:|--------|-------|:-------:|-------------|:---:|
| 1 | Crear Realm Keycloak + 5 SPIs | keycloak | 120s | Eliminar realm | < 10s |
| 2 | Crear Namespace K8s + NetworkPolicy + Quota | sbos-namespace | 30s | Eliminar namespace | < 5s |
| 3 | Provisionar SBOS_db + schemas + BDs apps | postgresql | 180s | Eliminar BDs y schemas | < 30s |
| 4 | Crear paths Vault + AppRole | vault | 180s | Eliminar paths | < 20s |
| 5 | Inicializar Context Registry Redis DB1 | redis | 120s | FLUSHDB DB1 | < 10s |
| 6 | DDL context_sessions + device_contexts | context | 60s | DROP TABLE | < 5s |
| 7 | Instalar fichas del tenant en orden DAG | varias | 600s | Compensación inversa | < 60s/ficha |

**SLO total:** tenant deploy < 30s P50, < 90s P99 (SBOS-PERF-001).

## 4. Compensación — el sistema nunca queda a medias

```
Paso 1: Realm Keycloak ✅
Paso 2: Namespace K8s ✅
Paso 3: PostgreSQL FALLA ❌ → dispara compensación
  → compensateStep2: eliminar namespace
  → compensateStep1: eliminar realm
  → Sistema vuelve a estado limpio
  → audit_event registrado: "saga aborted after step 3, 2 steps compensated"
```

## 5. Modos de ejecución

```bash
bosctl deploy seed-skull.yml              # producción: saga completa
bosctl deploy seed-skull.yml --dry-run    # validar dependencias sin ejecutar
bosctl deploy seed-skull.yml --step=3     # reanudar desde paso específico (recovery)
```
