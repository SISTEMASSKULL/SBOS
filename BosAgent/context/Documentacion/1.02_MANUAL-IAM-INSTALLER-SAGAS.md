## 1. Qué es una saga y por qué es obligatoria

Una saga es una secuencia de pasos con **compensación automática**. Si un paso falla, los
pasos anteriores se revierten en orden inverso. El sistema nunca queda en estado inconsistente.

**Fundamento normativo:**
- **OTel CNCF:** toda operación multi-servicio requiere trace context propagado
- **SRE (Google):** toda operación de infraestructura debe ser idempotente y reversible
- **ITIL 4 — Change Enablement:** todo cambio debe tener plan de rollback validado

## 2. La Gran Saga — `bosctl setup --mode=prod --seed ./seed-skull.yml`

Un solo comando. El BOS ejecuta 5 fases en secuencia. Cada fase es una mini-saga con
compensación. Si una fase falla, ESA fase se revierte. Las fases anteriores ya fueron
verificadas con sus criterios y no se tocan. No se avanza a la Fase N+1 hasta que todos
los criterios de la Fase N están en verde.

```
bosctl setup --mode=prod --seed ./seed-skull.yml
  │
  ├─ FASE 1: BOOTSTRAP (system-install + auto_bootstrap + runNormal)
  │   Sin compensación (es el sistema mismo). 10 pasos.
  │   Objetivo: daemon funcionando, socket /run/bos/bos.sock creado.
  │   Verify: C-01 ✅ C-02 ✅
  │
  ├─ FASE 2: STACK MÍNIMO (deployTenant — PASOS 0 a 6)
  │   Mini-saga con compensación. 7 pasos.
  │   Objetivo: K8s + PG + Redis + Vault + Keycloak + Context Plane DDL.
  │   Compensación: compensateSteps1..6 (implementado en deploy.go).
  │   Verify: C-03 ✅ C-04 ✅ C-05 ✅ C-06 ✅ C-07 ✅ C-08 ✅
  │
  ├─ FASE 3: DAEMONS Y APLICACIONES (deployTenant — PASO 7)
  │   Sin compensación individual (cada ficha es atómica).
  │   Objetivo: bauth, tryton, bnotify, bnexus, nextcloud, guacamole,
  │            fedora-logico, website-engine. Instalados en orden DAG.
  │   Verify: sockets responden ✅ health checks OK ✅
  │
  ├─ FASE 4: CONTEXT PLANE ACTIVACIÓN
  │   Mini-saga. 3 pasos.
  │   Objetivo: Context API :9443 operativa, flujo dctx_id→ctx_id verificado.
  │   Compensación: desactivar API, limpiar Redis DB1.
  │   Verify: device.register < 2s ✅ ctx_id lookup < 1ms P50 ✅
  │
  └─ FASE 5: VERIFICACIÓN VDI ✦
      Sin compensación (solo verificación). 6 criterios.
      Objetivo: certificar que todo funciona.
      Verify: C-09..C-14 todos ✅
      ✦ "El SBOS está instalado" ✦
```
