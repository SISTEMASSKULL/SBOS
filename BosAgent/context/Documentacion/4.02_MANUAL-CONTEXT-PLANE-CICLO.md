## 1. Flujo completo T+0 a T+fin

```
T+0     Dispositivo (Fedora físico/VDI) arranca
         → sbos-client → WebSocket mTLS :9444 → bhnexus
         → bos.ctx.device.register → dctx_id (UUIDv4, bitmask=0x0, TTL 8h)
         → Redis DB1: SET dctx:{id} {json}
         → PostgreSQL: INSERT INTO bos.registered_device
         → heartbeat cada 30s (renueva TTL)

T+N     Usuario presenta credencial (NFC, huella, contraseña)
         → banexus intercepta via udev → bhnexus → bAuth → BOS

T+N+8ms BOS recibe BitMask de bAuth (3 dominios: lógico, físico, financiero)
         → bos.ctx.promote(dctx_id, user, empresa, sucursal, loa, bitmask)
         → ctx_id generado (UUIDv4)
         → FK: ctx_id → dctx_id (trazabilidad pre-auth)
         → Redis DB1: SET ctx:{id} {json} (O(1) lookup para Kong)
         → PostgreSQL: INSERT INTO bos.context_session

T+N+15ms Capacidades activadas:
         Chapas: OPEN_RELAY emitido por bhnexus
         Apps: JWT con BitMask inyectado
         Cajón POS: actuador activado por banexus

T+op    CADA request del usuario:
         Kong → GET :9443/api/v1/context/{ctx_id} → Redis O(1) < 1ms
         Kong inyecta headers: X-SBOS-Tenant, X-SBOS-Empresa, X-SBOS-Sucursal,
         X-SBOS-Ctx-Id, X-SBOS-Bitmask

T+switch Usuario cambia de sucursal: bos.ctx.switch
         → ctx_id anterior → INVALIDADO
         → nuevo ctx_id con nueva sucursal, mismo user_id

T+fin   Logout / timeout KC:
         bos.ctx.invalidate(ctx_id) → Redis TTL=0 → state=INVALIDADO
         Chapas bloqueadas, apps bloqueadas, cajón bloqueado
         PostgreSQL: session preservada para auditoría perpetua
```

## 2. Estados del Contexto (bos_context_state_enum)

| Estado | Significado | Transición |
|--------|------------|------------|
| PENDIENTE | Dispositivo registrado, sin validar | → ACTIVO (al promote) |
| ACTIVO | Sesión operativa normal | → INVALIDADO / EXPIRADO |
| SUSPENDIDO | Suspendido por admin (tenant/user) | → ACTIVO (al reactivar) |
| BLOQUEADO | Bloqueado por política de seguridad | → ACTIVO (al resolver incidente) |
| INVALIDADO | Logout explícito o revocación (TERMINAL) | — |
| EXPIRADO | TTL agotado (TERMINAL) | — |
| ARCHIVADO | Movido a histórico, inmutable (TERMINAL) | — |

## 3. Lo que falta (8 TODOs bloqueantes)

1. **Heartbeat dctx_id:** sin keepalive, dispositivo expira en 8h aunque esté activo
2. **TTL enforcement activo:** solo `IsExpired()` pasiva, sin goroutine que escanee y expire
3. **Rate limiting:** sin token bucket, vulnerable a enumeración de ctx_id
4. **Audit events:** `internal/audit` nunca llamado desde handlers de contexto
5. **Sanitización:** ctx_id completos en logs, sin `logSanitize()`
6. **Health check:** sin health check específico para Context Plane
7. **Métricas:** `bos_ctx_sesiones_activas` gauge existe pero nunca se actualiza
8. **Cross-tenant validation:** `ListByTenant` acepta `tenant_id` sin verificar permisos
