## Por qué activar Branch Protection

Sin Branch Protection, cualquier commit roto puede llegar a `main` sin que
el pipeline tenga efecto práctico. Con Branch Protection activa:

- Ningún commit llega a `main` si `Build & Lint` o `Race Detection` fallan
- Los pushes directos a `main` quedan bloqueados (commits pasan por el CI primero)
- El historial de `main` queda limpio — todo commit en `main` pasó el HARD GATE

---

## Fase 1 — Configuración básica (activar ahora)

Ir a: **GitHub → Settings → Branches → Add branch protection rule**

```
Branch name pattern:  main

Checks a activar:
  ✅ Require status checks to pass before merging
     Status checks requeridos:
       - Build & Lint
       - Race Detection (HARD GATE)

  ✅ Require branches to be up to date before merging

  ❌ NO activar aún: "Restrict who can push to matching branches"
     (el equipo hace commits directos — activar en Fase 3)
```

**Verificar:** hacer un commit de prueba en una rama separada y abrir un PR.
El pipeline debe ejecutarse automáticamente. El merge debe bloquearse si falla.

---

## Fase 2 — Activar después de Fase 8 (tests ≥60%)

Cuando `go test -race -count=10 ./...` sea verde en Fase 8:

```
Actualizar la regla de main:
  ✅ Require status checks to pass before merging
     Status checks requeridos:
       - Build & Lint
       - Race Detection (HARD GATE)
       - Coverage (Warning Only)   ← agregar aquí, pero solo como info
```

**NO** bloquear merges por cobertura hasta que el equipo haya establecido
una baseline real. El coverage job tiene `continue-on-error: true` por esta razón.

## Fase 3 — Configuración estricta (cuando el equipo migre a PR workflow)

```
Branch name pattern:  main

  ✅ Require a pull request before merging
     Required approving reviews: 1
  ✅ Require status checks to pass before merging
     Status checks: Build & Lint, Race Detection
  ✅ Require branches to be up to date before merging
  ✅ Restrict who can push to matching branches
     Permitir: sistemasskull, bots de CI
  ✅ Require linear history (rebase & merge only)
  ❌ Allow force pushes: desactivado
  ❌ Allow deletions: desactivado
```

## Nota sobre el workflow actual (commit directo a main)

El equipo SKULL hace commits directos a `main`. Esto es válido mientras sea
un equipo pequeño coordinado. El pipeline CI actúa como red de seguridad
**post-commit**: si algo falla, el commit queda marcado con ❌ en GitHub y
el desarrollador recibe email inmediato.

Para migrar a PR-based workflow en el futuro, cambiar en `ci.yml`:
```yaml
on:
  push:
    branches: ["**"]
# →
on:
  push:
    branches: ["**"]
  pull_request:
    branches: [main]
```

Y activar Fase 3 de Branch Protection.
