## 1. Propósito de la integración

bkernel (SBOS Data Kernel) es el daemon que implementa el patrón CDC (Change Data Capture) sobre el WAL (Write-Ahead Log) de PostgreSQL. Su función es capturar cambios en SBOSDB y retransmitirlos como eventos en Redis Streams hacia los consumidores del ecosistema.

bNexus escribe en el WAL a través de sus inserts en `audit_events` y `ses_context`. bkernel captura esas escrituras y las retransmite para:
- Dashboard de control en bOS (análisis de flujos de acceso)
- bNotify (notificaciones push de accesos relevantes)
- bsearch (indexación de eventos — ver 6.03)

---

## 2. Qué escribe bhnexus en SBOSDB

bhnexus no escribe directamente en SBOSDB via ORM. Escribe a través de la capa de datos:

| Tabla | Cuándo | Qué contiene |
|-------|--------|-------------|
| `bos.audit_events` | Cada auth_request procesada | ctx_id, user_id, node_id, resultado, SAM-128, timestamp |
| `ses.ses_context` | Apertura/cierre de sesión shell (Shell Sentinel) | ctx_id, user_id, servicio PAM, IP remota, duración |
| `bos.audit_events` | Tamper/device_tamper | ctx_id, node_id, device_id, tipo de alerta, hash actual vs esperado |

### 2.1 Registro de auth_request en audit_events

```sql
-- Estructura del registro de auth_request
INSERT INTO bos.audit_events (
    event_id,           -- UUID v7 (monotónico por tiempo)
    ctx_id,             -- W3C traceparent "00-{trace_id}-{span_id}-01"
    entity_type,        -- 'nexus_auth'
    entity_id,          -- node_id (e.g. 'Ventas-01')
    subject_id,         -- user_id (UUID del usuario) | NULL si biométrico sin resolver
    action,             -- 'auth_granted' | 'auth_denied' | 'auth_step_up'
    resource_type,      -- 'physical_zone' | 'logical_resource' | 'shell_session'
    resource_id,        -- zone_id o device_id
    outcome,            -- 'success' | 'failure' | 'pending'
    metadata,           -- JSONB: sam128, credential_type, latency_ms, actuator_commands
    created_at          -- TIMESTAMPTZ con precisión µs
) VALUES (...);
```

### 2.2 Contenido del campo metadata (JSONB)

```json
{
  "credential_type": "qr_dynamic",
  "sam128_word_a":   "0x...",
  "sam128_word_b":   "0x...",
  "bauth_latency_ms": 4,
  "cache_used":       false,
  "actuator_commands": [
    {"target": "DRAWER_01", "action": "OPEN", "duration_ms": 5000}
  ],
  "node_id":    "Ventas-01",
  "device_id":  "PHY_DEV_QR_VENTAS_01",
  "protocol":   "usb_hid"
}
```

## 3. Slot de replicación lógica

bkernel consume los cambios del WAL de PostgreSQL mediante un replication slot:

```sql
-- Slot creado por bkernel durante su provisioning
SELECT pg_create_logical_replication_slot('bkernel_audit', 'pgoutput');

-- bkernel suscribe a las tablas de bhnexus
-- Publication creada al hacer deploy de SBOSDB:
CREATE PUBLICATION bkernel_nexus_pub
  FOR TABLE bos.audit_events, ses.ses_context
  WITH (publish = 'insert');  -- solo inserts (audit es append-only)
```

### 3.1 Protocolo pgoutput

bkernel usa el plugin de decodificación lógica `pgoutput` (nativo de PostgreSQL 10+, sin extensiones adicionales). El formato de cada mensaje WAL que bkernel recibe:

```
Relation:  table OID, nombre, columnas
Begin:     XID de la transacción
Insert:    tupla completa con todos los campos
Commit:    timestamp de la transacción
```

bkernel transforma este formato en eventos Redis Streams con la estructura SBOS estándar.

---

## 4. Evento Redis Stream emitido por bkernel

Por cada `INSERT` en `bos.audit_events` que corresponde a un evento de bNexus, bkernel emite un mensaje al stream Redis `sbos:events:nexus`:

```redis
XADD sbos:events:nexus * \
  event_id       "uuid-v7" \
  ctx_id         "00-trace-span-01" \
  entity_type    "nexus_auth" \
  entity_id      "Ventas-01" \
  subject_id     "uuid-cajero" \
  action         "auth_granted" \
  resource_type  "physical_zone" \
  resource_id    "zona-cajas-01" \
  metadata       "{\"credential_type\":\"qr_dynamic\",\"sam128_word_a\":\"0x...\"}" \
  created_at     "2026-08-04T10:14:55.123456Z"
```

### 4.1 Consumidores registrados del stream `sbos:events:nexus`

| Consumer Group | Daemon | Uso |
|---------------|--------|-----|
| `bos-dashboard` | bOS | Dashboard de control de acceso en tiempo real |
| `bnotify-nexus` | bNotify | Notificaciones push de accesos críticos o denegados |
| `bsearch-nexus` | bsearch | Indexación de eventos para búsqueda semántica |

## 5. Latencia de la cadena WAL

```
T+0ms     auth_request llega a bhnexus
T+12ms    SAM-128 obtenido, actuador activado
T+13ms    bhnexus escribe en bos.audit_events (INSERT async, no bloquea el flujo auth)
T+15ms    PostgreSQL escribe el registro en el WAL
T+20ms    bkernel detecta el cambio en el slot de replicación
T+25ms    bkernel emite el evento en Redis Stream sbos:events:nexus
T+30ms    Consumidores (bOS/bNotify/bsearch) reciben el evento
```

La latencia desde el evento de autenticación hasta que está disponible en el Redis Stream es de aproximadamente **17ms** (T+13ms → T+30ms). El flujo de autenticación no espera este proceso — es completamente asíncrono.

---

## 6. Retención y purga

El slot de replicación `bkernel_audit` consume los WAL segmentos en tiempo real. Una vez que bkernel ha procesado un segmento, PostgreSQL puede limpiar el WAL. Si bkernel falla y no consume durante un período prolongado, el WAL puede crecer indefinidamente.

**Mitigación**: bkernel tiene un watchdog que alerta si el lag del slot supera 10,000 transacciones. Si supera 100,000, alerta CRÍTICO y el slot puede necesitar reset.

```bash
# Ver lag actual del slot bkernel_audit
SELECT slot_name, pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) as lag
FROM pg_replication_slots
WHERE slot_name = 'bkernel_audit';
```

## 7. Eventos de tamper en el WAL

Los eventos de integridad comprometida (Integrity Monitor de banexus) también llegan al WAL:

```sql
INSERT INTO bos.audit_events (
    event_id, ctx_id, entity_type, entity_id, action, outcome, metadata, created_at
) VALUES (
    gen_random_uuid(),
    '00-...',
    'nexus_integrity',
    'Ventas-01',           -- node_id
    'integrity_breach',
    'failure',
    '{
      "actual_hash":   "sha256:...",
      "expected_hash": "sha256:...",
      "auto_shutdown": true,
      "exit_code": 99
    }',
    now()
);
```

bkernel emite este evento al stream `sbos:events:security` con prioridad inmediata, donde bOS lo procesa para alertar al operador.
