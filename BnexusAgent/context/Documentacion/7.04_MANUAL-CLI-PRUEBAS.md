## 1. bnexusctl — descripción

`bnexusctl` es la CLI de administración de bNexus. Se comunica con bhnexus a través del socket Interface Dual (`/run/bos/bhnexus.sock`) usando JSON-RPC 2.0. No requiere acceso directo a la base de datos ni a los sockets internos.

```
bnexusctl [COMANDO] [SUBCOMANDO] [FLAGS]

Comandos principales:
  node        Gestión de nodos banexus (listar, estado, desconectar)
  device      Gestión de dispositivos hardware (listar, estado, test)
  auth        Operaciones de autorización (test-flow, cache, invalidar)
  policy      Gestión de policies (estado, push, sincronizar)
  metrics     Ver métricas Prometheus en tiempo real
  audit       Consultar audit trail (últimos eventos, filtros)
  health      Estado general del daemon y dependencias
  version     Versión del binario y protocolo
```

## 2. Comandos de nodos

### 2.1 Listar nodos conectados

```bash
bnexusctl node list

# Salida:
NODE_ID          STATUS     UPTIME     CACHE_ENTRIES  LAST_AUTH
Ventas-01        CONNECTED  2d 3h 12m  12             2026-08-04T10:14:23Z
Almacen-01       CONNECTED  5h 44m     3              2026-08-04T09:55:11Z
Gerencia-01      OFFLINE    —          0              2026-08-03T17:30:00Z

# Con filtro de estado
bnexusctl node list --status=offline
```

### 2.2 Estado detallado de un nodo

```bash
bnexusctl node status Ventas-01

# Salida (JSON):
{
  "node_id": "Ventas-01",
  "status": "CONNECTED",
  "spiffe_id": "spiffe://sbos.skull/agent/banexus/Ventas-01",
  "connected_since": "2026-08-02T07:00:00Z",
  "last_heartbeat": "2026-08-04T10:14:50Z",
  "uptime_seconds": 184800,
  "active_sessions": 2,
  "cache_entries": 12,
  "integrity_ok": true,
  "banexus_version": "1.0.0",
  "bhnexus_ctx": "server-side-ctx-id"

```

### 2.3 Desconectar un nodo (mantenimiento)

```bash
# Desconexión limpia — el nodo puede reconectarse
bnexusctl node disconnect Ventas-01 --reason "mantenimiento programado"

# Blacklist permanente (requiere aprobación humana — HITL)
# bnexusctl node blacklist Ventas-01  # No disponible via CLI — se hace via bAuth
```

```bash

# El operador debe tener el átomo nexus.actuate.test en su BitMask
```

```bash
# Simula un auth_request completo sin activar el actuador físico
bnexusctl auth test-flow \
```

## 5. Verificación de Puerta 1 (banexus ↔ bhnexus)

### 5.1 Verificación del WebSocket mTLS

```bash
# Test de conexión WebSocket mTLS desde el host de bhnexus
# Usando openssl s_client para verificar TLS
openssl s_client \
  -connect localhost:9444 \
  -cert /etc/bos/tls/bhnexus.crt \
  -key /etc/bos/tls/bhnexus.key \
  -CAfile /etc/bos/tls/ca.crt \
  -tls1_3 \
  -verify_return_error 2>&1 | grep -E "Verify|Protocol|Cipher|CONNECTED"

# Salida esperada:
# CONNECTED(00000003)
# Protocol  : TLSv1.3
# Cipher    : TLS_AES_256_GCM_SHA384
# Verify return code: 0 (ok)
```

### 5.2 Verificación del SPIFFE ID en el certificado de un nodo

```bash
# Verificar el SPIFFE ID en el certificado de banexus del nodo Ventas-01
openssl x509 -in /etc/banexus/tls/agent.crt -noout -text | grep "URI:"

# Salida esperada:
# URI:spiffe://sbos.skull/agent/banexus/Ventas-01
```

### 5.3 Prueba de heartbeat (desde banexus)

```bash
# En el host donde corre banexus, enviar un heartbeat manual via bnexusctl local
bnexusctl heartbeat --node-id Ventas-01

# Salida:
{
  "status": "OK",
  "bhnexus_response": "ACK",
  "latency_ms": 3
}
```

## 6. Verificación de Puerta 2 (bhnexus ↔ bAuth)

### 6.1 Verificación del Sub-canal A (unix socket TLV)

```bash
# Verificar que el socket existe y tiene los permisos correctos
ls -la /run/bos/bauth.sock
# Esperado: srwxrw---- bauth bos-group ... /run/bos/bauth.sock

# Test de consulta de bitmask (modo diagnóstico)
bnexusctl auth bitmask-request \
  --user-id "uuid-cajero" \
  --node-id "Ventas-01" \
  --via sub-canal-a

# Salida:
{
  "status": "granted",
  "latency_ms": 4,
  "socket_used": "/run/bos/bauth.sock",
  "sam128_word_a": "0x...",
  "sam128_word_b": "0x..."
}
```

### 6.2 Verificación del Sub-canal B (canal privilegiado)

```bash
# Verificar que bhnexus creó el socket y bAuth está conectado
ls -la /run/bos/bauth-nexus.sock
# Esperado: srwxrw---- bhnexus bos-group ... /run/bos/bauth-nexus.sock

# Verificar conexión activa de bAuth al sub-canal B
ss -xp | grep "bauth-nexus"
# Esperado: u_str ... /run/bos/bauth-nexus.sock ... pid=<bauth-pid>

# Test de evento device_tamper (modo dry-run)
bnexusctl auth privileged-test --event device_tamper --node-id Ventas-01 --dry-run
```

### 6.3 Test de latencia end-to-end

```bash
# Mide la latencia completa: auth_request → bAuth → SAM-128 → respuesta
bnexusctl auth latency-test --iterations 100 --user-id "uuid-cajero" --node-id Ventas-01

# Salida:
Iteraciones: 100
Cache hits:  87 (87.0%)
Cache misses: 13 (13.0%)

Latencia con cache hit:
  p50: 0.8ms
  p95: 1.2ms
  p99: 1.8ms

Latencia sin cache (bAuth round-trip):
  p50: 6.2ms
  p95: 9.1ms
  p99: 11.4ms
```

## 7. Prueba de integridad de banexus

```bash
# Verificar integridad del binario manualmente (en el host de banexus)
sha256sum /opt/banexus/banexus
cat /etc/banexus/banexus.sha256

# Los hashes deben coincidir

# Verificar la firma Ed25519 del hash canónico
openssl dgst -sha256 -verify /etc/banexus/vault_ca.pem \
  -signature /etc/banexus/banexus.sha256.sig \
  /etc/banexus/banexus.sha256
# Salida esperada: Verified OK
```
