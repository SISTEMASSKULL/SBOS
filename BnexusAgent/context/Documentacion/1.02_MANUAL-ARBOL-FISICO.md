## 1. El árbol como columna vertebral física

bNexus organiza el espacio físico en un árbol jerárquico de 11 niveles. Este árbol es la referencia geográfica y organizacional que permite:

- Definir políticas por ubicación (security_level por zona)
- Resolver permisos físicos con herencia (un permiso en zona cubre sub-nodos)
- Identificar dónde está cada dispositivo y qué controla
- Establecer la cadena de auditoría completa (user → device → zone → building → site)

El árbol físico se **almacena en SBOSDB** como entidades en `idn_identity_entity`. No existe un árbol YAML paralelo.

## 2. Los 11 niveles

```
NIVEL 0  TENANT
  → El servidor SBOS de la organización. Límite de soberanía.
  → No es una zona física — es el contenedor de toda la jerarquía.
  → Un servidor SBOS = un TENANT.

NIVEL 1  REGIÓN / PAÍS
  → División geopolítica superior.
  → Governa: timezone, normativa fiscal, retención de logs.
  → Ejemplo ID: PHY_REGION_BO (Bolivia), PHY_REGION_AR (Argentina)

NIVEL 2  CIUDAD / MUNICIPIO
  → Subdivisión de la región.
  → Ejemplo: PHY_CITY_LPZ (La Paz), PHY_CITY_CBB (Cochabamba)

NIVEL 3  SITIO / CAMPUS
  → Dirección física específica donde la organización opera.
  → Puede haber múltiples sitios por ciudad.
  → Governa: schedule_default (horario base del sitio), holiday_calendar.
  → Ejemplo: PHY_SITE_LPZ_001 — "Av. Camacho 1234, La Paz"

NIVEL 4  EDIFICIO / ESTRUCTURA
  → Edificio dentro del sitio.
  → Ejemplo: PHY_BLDG_A (Edificio A), PHY_BLDG_ALMACEN (Almacén)

NIVEL 5  PLANTA / PISO
  → Nivel vertical dentro del edificio.
  → Primer nivel donde se asignan dispositivos físicos.
  → Ejemplo: PHY_FLOOR_PB (Planta Baja), PHY_FLOOR_1 (Piso 1)

NIVEL 6  ZONA / ÁREA
  → Área funcional dentro de la planta con security_level propio.
  → security_level 1 = público, 2 = empleados, 3 = restringido, 4 = crítico.
  → Ejemplo: PHY_ZONE_VENTAS (sl=2), PHY_ZONE_ADMIN (sl=2), PHY_ZONE_IT (sl=3)

NIVEL 7  ESPACIO / HABITACIÓN / SALA
  → Espacio delimitado dentro de una zona.
  → Ejemplo: PHY_ROOM_JUNTAS, PHY_ROOM_SERVIDOR, PHY_ROOM_BOVEDA
  → Espacios críticos: security_level 3-4.

NIVEL 8  PUNTO DE ACCESO
  → Apertura física entre espacios (puerta, ventana, barrera).
  → Ejemplo: PHY_AP_VENTAS_PUERTA_PRIN, PHY_AP_SALA_SERV_PUERTA

NIVEL 9  CERRADURA / CONTROL
  → Mecanismo que controla el punto de acceso.
  → mode: fail_secure (cierra sin poder) | fail_safe (abre sin poder).
  → REGLA LEGAL: puertas de emergencia/escape SIEMPRE son fail_safe.

NIVEL 10 DISPOSITIVO / LECTOR
  → Hardware que captura la credencial.
  → Referencia al driver en el HAL: protocolo y parámetros de conexión.
  → Ejemplo: PHY_DEV_QR_ZV_PUERTA_PRIN (lector QR OSDP v2)
             PHY_DEV_FP_SALA_SERV (lector dactilar OSDP biométrico)
             PHY_DEV_NFC_ACC_PRIN (lector NFC DESFire)
```

## 4. Herencia de permisos

Un permiso concedido en un nivel superior cubre **automáticamente** todos los sub-nodos del árbol. Una restricción explícita en un nivel inferior prevalece sobre la herencia.

```
Ejemplo: ROL_SUPERVISOR tiene acceso a PHY_SITE_LPZ_001
  → Cubre: PHY_BLDG_OFICINAS + PHY_BLDG_ALMACEN
  → Cubre: todos los pisos, zonas, salas y dispositivos bajo esos edificios
  → EXCEPCIÓN: PHY_ROOM_SERVIDOR tiene security_level=4
    → Si ROL_SUPERVISOR no tiene el bit de sl=4 en su SAM-128 → DENIED
    → La restricción del nivel 7 prevalece sobre el permiso del nivel 3

Ejemplo: ROL_CAJERO tiene acceso a PHY_ZONE_VENTAS
  → Cubre: todas las puertas y lectores dentro de PHY_ZONE_VENTAS
  → NO cubre: PHY_ZONE_ADMIN (zona distinta, sin herencia)
```

La herencia se evalúa en el SAM-128 (WORD-A bits 8-15 = zonas autorizadas). El árbol físico informa a bAuth qué zonas tiene habilitadas el usuario — bAuth calcula el bitmask de zonas al emitir el SAM-128.

## 5. Security level por nivel

| Nivel | Security Level típico | Roles mínimos |
|-------|----------------------|---------------|
| Público (acceso libre) | 0 | Sin autenticación |
| Empleados | 1 | AAL1 — contraseña |
| Zona operacional | 2 | AAL2 — contraseña + MFA |
| Zona restringida | 3 | AAL2 + mTLS workstation |
| Zona crítica | 4 | AAL3 — biométrico o hardware key |

---

## 6. IDs de zona en el SAM-128

Los 8 bits de zona (WORD-A bits 8-15) del SAM-128 representan zonas del árbol físico. La correspondencia exacta la configura bAuth al emitir el SAM-128:

```
bit 8  → zona_0: PHY_ZONE_VENTAS    (security_level=2)
bit 9  → zona_1: PHY_ZONE_ADMIN     (security_level=2)
bit 10 → zona_2: PHY_ZONE_IT        (security_level=3)
bit 11 → zona_3: PHY_ROOM_SERVIDOR  (security_level=4)
bit 12 → zona_4: PHY_ZONE_ALM       (security_level=2)
bit 13 → zona_5: (reservado)
bit 14 → zona_6: (reservado)
bit 15 → zona_7: (reservado)
```

Un usuario con ROL_CAJERO: `word_a bits 8-15 = 0b00000001` (solo zona_0 = VENTAS).  
Un usuario con ROL_SUPERVISOR: `word_a bits 8-15 = 0b00011111` (VENTAS+ADMIN+IT+SERVIDOR+ALM).

## 7. Fail-safe vs fail-secure

El nivel 9 (CERRADURA/CONTROL) define el comportamiento ante pérdida de energía:

| Modo | Comportamiento | Cuándo usar |
|------|---------------|-------------|
| **fail_secure** | Se cierra y bloquea sin energía | Puertas de oficina, sala de servidores, bóveda — la seguridad es prioritaria |
| **fail_safe** | Se abre sin energía | Puertas de emergencia/evacuación — obligatorio por normativa de seguridad laboral y contra incendios |

**Regla legal:** toda puerta en una ruta de evacuación DEBE ser fail_safe. No es opcional — es una exigencia legal en Bolivia (NB 58009) y en la mayoría de países. bOS rechaza una ficha fail_secure en una zona marcada como ruta de evacuación.
