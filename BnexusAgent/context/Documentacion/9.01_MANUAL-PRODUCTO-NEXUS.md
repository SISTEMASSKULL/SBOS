## 1. Qué es bNexus como producto

bNexus es el **conectividad y control físico soberano** del ecosistema SBOS. No es un PACS (Physical Access Control System) standalone — es la capa que conecta el mundo físico (hardware, sensores, actuadores, personas con credenciales) con el mundo lógico (identidades, roles, políticas definidas en bAuth).

**bNexus como extensión de bAuth**: bNexus no toma decisiones de acceso. bAuth es el único PDP. bNexus es el brazo ejecutor que lleva las decisiones de bAuth hasta el hardware físico.

### 1.1 Lo que bNexus ES

| Capacidad | Descripción |
|-----------|-------------|
| **Broker de conectividad física** | Une bAuth con el hardware (cerraduras, sensores, cámaras) |
| **Interceptor soberano** | Captura credenciales del hardware antes de que lleguen a evdev o a otras apps |
| **Distribuidor del SAM-128** | Lleva la autorización exacta a cada nodo y actúa en consecuencia |
| **Normalizador de protocolos** | OSDP + Wiegand + MQTT + ONVIF + BLE + USB HID → un único CredentialEvent |
| **Ejecutor atómico** | Abre la puerta + abre el cajón + activa la alarma + registra en auditoría en una sola transacción |
| **Centinela de integridad** | Verifica que el agente de borde no ha sido modificado |

### 1.2 Lo que bNexus NO ES

| Confusión frecuente | Realidad |
|--------------------|----------|
| PACS standalone | Depende de bAuth para toda decisión — no funciona sin bAuth |
| Sistema de vigilancia CCTV | No almacena video — solo extrae face hash del evento ONVIF |
| PDP (Policy Decision Point) | El PDP es bAuth — bNexus solo aplica |
| Sistema con lógica de negocio | La lógica de negocio vive en bAuth (roles, átomos, dominios) |

## 2. Binarios del producto

| Binario | Descripción | Entorno de ejecución | Ubicación |
|---------|-------------|---------------------|-----------|
| `bhnexus` | Broker central — acepta conexiones de todos los nodos banexus | Servidor central SBOS | `/opt/bhnexus/bhnexus` |
| `banexus` | Agente de borde — controla hardware local + PAM + Integrity Monitor | Workstation / POS / gateway SBC | `/opt/banexus/banexus` |
| `bnexusctl` | CLI de administración — se comunica con bhnexus via JSON-RPC | Cualquier host con acceso al socket | `/usr/local/bin/bnexusctl` |

### 2.1 Distribución por forma de banexus

| Forma banexus | Binario | Plataforma | Caso de uso |
|--------------|---------|------------|-------------|
| banexus-implicit | No tiene | Cualquier app | Toda app de software — solo mTLS + JWT |
| banexus-daemon | `banexus` (MUSL) | Linux x86_64 / ARM64 | Workstation, POS con hardware físico |
| banexus-gateway | `banexus --mode=gateway` (MUSL) | Linux ARM (Raspberry Pi) | Sitio remoto con hardware mudo |
| banexus-sdk | SDK nativo iOS/Android | iOS 16+ / Android 12+ | Credencial móvil BLE/UWB/NFC |
| banexus-virtual | No tiene | Firmware | Dispositivo que llama a bAuth directamente |

## 3. Métodos JSON-RPC — bhnexus.*

bhnexus expone su API vía JSON-RPC 2.0 sobre el socket `/run/bos/bhnexus.sock` (Interface Dual ADR-020). Los métodos se agrupan por área funcional.

### 3.1 Gestión de nodos

| Método | Parámetros | Retorno | Descripción |
|--------|-----------|---------|-------------|
| `bhnexus.node.list` | `{ status?: string }` | `Node[]` | Lista nodos banexus (todos o filtrado por estado) |
| `bhnexus.node.status` | `{ node_id: string }` | `NodeStatus` | Estado detallado de un nodo |
| `bhnexus.node.disconnect` | `{ node_id, reason }` | `{ ok }` | Desconecta un nodo limpiamente |
| `bhnexus.node.heartbeat_last` | `{ node_id }` | `Heartbeat` | Último heartbeat recibido del nodo |
| `bhnexus.node.metrics` | `{ node_id }` | `NodeMetrics` | Métricas del nodo (desde heartbeats acumulados) |

### 3.2 Gestión de dispositivos hardware

| Método | Parámetros | Retorno | Descripción |
|--------|-----------|---------|-------------|
| `bhnexus.device.list` | `{ protocol?: string, status?: string }` | `Device[]` | Lista dispositivos HAL |
| `bhnexus.device.status` | `{ device_id }` | `DeviceStatus` | Estado detallado del dispositivo |
| `bhnexus.device.actuate` | `{ device_id, target, action, duration_ms, ctx_id }` | `{ ok, latency_ms }` | Activa un actuador (requiere privilegio nexus.actuate) |
| `bhnexus.device.health` | `{ device_id }` | `DeviceHealth` | Health check del driver |
| `bhnexus.device.driver_list` | `{}` | `Driver[]` | Lista los 6 drivers disponibles |

### 3.3 Autorización y cache

| Método | Parámetros | Retorno | Descripción |
|--------|-----------|---------|-------------|
| `bhnexus.auth.request` | `{ node_id, credential_type, payload, ctx_id }` | `AuthResponse` | Auth request manual (diagnóstico) |
| `bhnexus.auth.cache_status` | `{}` | `CacheStats` | Estado del Auth Cache (hits, misses, entries) |
| `bhnexus.auth.cache_invalidate` | `{ user_id?, node_id?, reason }` | `{ invalidated }` | Invalida entradas del cache |
| `bhnexus.auth.bitmask_request` | `{ user_id, node_id, ctx_id }` | `BitMaskBundle` | Consulta bitmask directamente a bAuth (diagnóstico) |
| `bhnexus.auth.latency_test` | `{ iterations, user_id, node_id }` | `LatencyReport` | Test de latencia end-to-end |

### 3.4 Gestión de políticas

| Método | Parámetros | Retorno | Descripción |
|--------|-----------|---------|-------------|
| `bhnexus.policy.push` | `{ node_id?, user_id?, reason }` | `{ nodes_updated }` | Fuerza push de policy a nodo(s) |
| `bhnexus.policy.sync_status` | `{ node_id }` | `SyncStatus` | Estado de sincronización del policy cache |
| `bhnexus.policy.snapshot` | `{ node_id }` | `PolicySnapshot` | Snapshot completo de policies del nodo |

### 3.5 Monitoreo y auditoría

| Método | Parámetros | Retorno | Descripción |
|--------|-----------|---------|-------------|
| `bhnexus.metrics.prometheus` | `{}` | `string` | Texto completo en formato OpenMetrics |
| `bhnexus.metrics.summary` | `{}` | `MetricsSummary` | Resumen JSON de las métricas clave |
| `bhnexus.audit.events` | `{ node_id?, since?, limit? }` | `AuditEvent[]` | Últimos eventos de auditoría |
| `bhnexus.audit.event` | `{ ctx_id }` | `AuditEvent` | Evento específico por ctx_id |

### 3.6 Administración del daemon

| Método | Parámetros | Retorno | Descripción |
|--------|-----------|---------|-------------|
| `bhnexus.health` | `{}` | `HealthReport` | Estado completo del daemon y dependencias |
| `bhnexus.version` | `{}` | `VersionInfo` | Versión del binario y protocolo |
| `bhnexus.config.reload` | `{}` | `{ ok }` | Recarga bhnexus.toml sin reiniciar (SIGHUP) |
| `bhnexus.config.current` | `{}` | `Config` | Configuración activa (sin secretos) |

## 5. Propuesta de valor para el cliente SBOS

### 5.1 Sin bNexus vs con bNexus

| Escenario | Sin bNexus | Con bNexus |
|-----------|-----------|-----------|
| Acceso físico | Sistema PACS separado (Lenel, Genetec, Bosch) con licencias externas | Integrado en bAuth — sin licencias adicionales |
| Identidad física | Base de datos de tarjetas separada de la identidad digital | Una sola identidad en SBOSDB controla físico + lógico |
| Auditoría | Logs en sistema PACS separado | Un audit trail unificado con ctx_id en bAuth |
| Hardware | Protocolos silos (OSDP solo con su software, MQTT solo con su software) | HAL unificado: OSDP + MQTT + ONVIF + BLE + USB HID + HTTP |
| SSH | Sin control de acceso a shell | Shell Sentinel: PAM + LD_PRELOAD + eBPF + ctx_id en cada sesión |
| Biometría | Templates almacenados en servidor (riesgo RGPD) | Solo el hash viaja — la imagen nunca sale del chip |

### 5.2 Escalabilidad

| Dimensión | Límite de diseño |
|-----------|-----------------|
| Nodos banexus simultáneos | 10,000 por instancia bhnexus |
| Auth requests/segundo | 50,000 req/s con cache hit |
| Dispositivos HAL por bhnexus | 500 (100 por driver) |
| Entradas en Auth Cache | 10,000 (LRU, ~15MB RAM) |
| Latencia con cache hit | < 2ms end-to-end |
| Latencia sin cache (bAuth) | < 15ms end-to-end |

## 6. Posicionamiento en el ecosistema SBOS

```
ECOSISTEMA SBOS
─────────────────────────────────────────────────────────────────
bos      → Infrastructure Provisioning & Lifecycle Orchestrator
bauth    → Identity Control Plane (PDP soberano)
│
├── bhnexus → Nexus Host (broker central de conectividad física)
│   │
│   └── banexus → Nexus Agent (agente de borde × N nodos)
│
bkernel  → CDC WAL → Redis Streams
biedata  → JSON-RPC Orquestador de datos
bsearch  → Motor de búsqueda soberano
bnotify  → Push MFA y notificaciones
─────────────────────────────────────────────────────────────────
```

bNexus consume de bAuth (identidad) y bOS (provisioning). Produce hacia bkernel (WAL), bsearch (indexación) y bnotify (alertas de acceso).
