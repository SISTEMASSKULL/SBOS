# 6.03 — Integración bNexus ↔ bsearch (indexación)
## Indexación de eventos de autenticación para búsqueda semántica soberana

**Versión:** 1.0.0  
**Fecha:** 2026-08-04  
**Fuente:** SBOS_bhnexus_INTEGRACIONES.md INT-BHNEXUS-004  
**Carta rectora:** `0.00_MANUAL-DIRECTRICES-NEXUS.md`  

---

## 1. Propósito de la integración

bsearch (SBOS Búsqueda Soberana) es el motor de búsqueda del ecosistema, implementado sobre PostgreSQL 18+ con búsqueda de texto completo y vectorial soberana. La integración con bNexus permite:

- **Auditoría forense**: buscar todos los accesos de un usuario, nodo o zona en un rango de tiempo
- **Análisis de patrones**: detectar anomalías en la frecuencia o distribución de accesos
- **Cumplimiento**: generar informes de acceso para auditorías ISO 27001
- **Investigación de incidentes**: trazar el recorrido de un usuario por las zonas físicas

---

## 2. Flujo de indexación

bhnexus envía eventos a bsearch de forma **asíncrona** — nunca bloquea el flujo de autenticación:

```
T+0ms    auth_request llega a bhnexus
T+12ms   SAM-128 obtenido, actuador activado (flujo principal)
T+13ms   bhnexus encola el evento para indexación (tokio channel no bloqueante)
T+15ms   Worker de indexación saca el evento de la cola
T+17ms   HTTP POST a bsearch (asíncrono, no bloquea T+12ms)
```

El worker de indexación tiene una cola de hasta 10,000 eventos. Si bsearch está caído, los eventos se acumulan en la cola y se reintentan con backoff exponencial.

---

## 3. Endpoint de indexación

```
POST http://bsearch:9220/v1/index/event
Content-Type: application/json
X-Ctx-Id: 00-{trace_id}-{span_id}-01
```

**Timeout**: 5 segundos  
**Retries**: 2 (con delays de 1s y 3s)  
**Comportamiento si falla**: el evento se loguea con WARNING y se descarta (no es crítico para la autenticación)

---

## 4. Tipos de eventos indexados

| Tipo de evento | Cuándo se genera | Prioridad de indexación |
|---------------|-----------------|:-----------------------:|
| `auth_granted` | Autenticación exitosa | Normal |
| `auth_denied` | Credencial inválida o BitMask insuficiente | High (anomalía potencial) |
| `auth_timeout` | Timeout en lectura de credencial del hardware | Normal |
| `device_error` | Error de hardware (lector desconectado, tamper) | High |
| `policy_update` | Invalidación de cache aplicada en el nodo | Normal |
| `integrity_breach` | binario banexus comprometido | CRITICAL (inmediato) |
| `node_offline` | banexus desconectado > 30 min | High |

## 6. Índice `sbos_nexus_events` en bsearch

bsearch crea el índice `sbos_nexus_events` con las siguientes configuraciones:

### 6.1 Campos indexados

| Campo | Tipo de índice | Para qué |
|-------|---------------|---------|
| `ctx_id` | Hash | Lookup exacto por trazabilidad |
| `timestamp` | BTree | Rangos de tiempo (auditoría forense) |
| `actor.user_id` | Hash + BTree | Todos los accesos de un usuario |
| `actor.node_id` | Hash | Todos los accesos desde un nodo |
| `resource.zone_id` | Hash | Todos los accesos a una zona |
| `event_type` | Hash | Filtrar por tipo (denied, breach...) |
| `credential.type` | Hash | Análisis por tipo de credencial |
| `decision.outcome` | Hash | Filtrar granted/denied |
| texto completo | GIN tsvector | Búsqueda semántica en zona_name, tags |

### 6.2 Consultas frecuentes

```sql
-- Todos los accesos de un usuario en las últimas 24h
SELECT * FROM sbos_nexus_events
WHERE actor->>'user_id' = 'uuid-cajero'
  AND timestamp > now() - interval '24 hours'
ORDER BY timestamp DESC;

-- Accesos denegados en zona crítica (sl >= 3) en la última semana
SELECT actor->>'user_id', count(*), max(timestamp)
FROM sbos_nexus_events
WHERE event_type = 'auth_denied'
  AND (resource->>'sl_level')::int >= 3
  AND timestamp > now() - interval '7 days'
GROUP BY actor->>'user_id'
ORDER BY count(*) DESC;

-- Búsqueda semántica: "accesos al servidor de datos"
SELECT * FROM sbos_nexus_events
WHERE to_tsvector('spanish', resource->>'zone_name') @@ plainto_tsquery('spanish', 'servidor datos')
ORDER BY timestamp DESC LIMIT 50;
```

## 7. Retención y políticas de purga

bsearch aplica las siguientes políticas de retención a `sbos_nexus_events`:

| Tipo de evento | Retención | Justificación |
|---------------|-----------|---------------|
| `auth_granted` normal | 90 días | Auditoría ISO 27001 básica |
| `auth_denied` | 180 días | Análisis de intentos de acceso |
| `integrity_breach` | 3 años | Evidencia forense |
| `auth_granted` zona sl=4 | 1 año | Cumplimiento zonas críticas |
| `device_error` | 90 días | Mantenimiento predictivo |

La purga se ejecuta automáticamente por bsearch mediante particionamiento por tiempo (PostgreSQL 18 `PARTITION BY RANGE (timestamp)`).

---

## 8. Dependencia y degradación

| Estado de bsearch | Impacto en bNexus |
|------------------|-------------------|
| **Online** | Indexación normal, cola vacía |
| **Degradado (lento)** | Cola crece, reintentos con backoff |
| **Offline** | Cola se llena hasta 10K eventos; eventos más antiguos se descartan con WARNING |
| **Recuperado** | Cola se vacía en orden (FIFO); eventos dentro de ventana de retención se indexan |

bsearch es una **dependencia opcional** de bNexus (ver matriz de dependencias en SBOS_bhnexus_INTEGRACIONES.md §3). Su ausencia no afecta la autenticación.
