## 1. Qué es el Shell Sentinel

El Shell Sentinel es el componente de banexus que controla y audita **el acceso a sesiones de shell** (SSH, TTY local, sudo) y **la ejecución de comandos privilegiados** en workstations y servidores donde banexus está instalado.

Su mecanismo técnico es un módulo PAM (`pam_banexus.so`) que se inserta en el stack de autenticación PAM del host. Cuando un usuario intenta abrir una sesión SSH o ejecutar sudo, PAM llama a `pam_banexus.so`, que consulta a bhnexus para decidir si el usuario tiene autorización.

---

## 2. Posición en el stack PAM

```
/etc/pam.d/sshd (o sudo, login, etc.):

auth    required    pam_unix.so          # verificación de contraseña Unix
auth    required    pam_banexus.so       # verificación de bAuth vía bhnexus
                    banexus_socket=/run/banexus/pam.sock
                    timeout_ms=5000
                    fail_open=false      # fail-secure: si bhnexus no responde → DENY

account required    pam_unix.so
account required    pam_banexus.so       # verificación de acceso a la sesión

session required    pam_unix.so
session required    pam_banexus.so       # abre el audit trail de la sesión
```

`fail_open=false` es el valor obligatorio — si bhnexus no responde en `timeout_ms`, la autenticación falla. No se permite sesión sin verificación.

## 3. El flujo de autenticación PAM

### 3.1 ssh usuario@servidor

```
T+0ms   Usuario ejecuta: ssh carlos@servidor.skull.bo

T+1ms   sshd inicia autenticación:
        sshd llama stack PAM con username="carlos", remote_ip="10.0.1.45"

T+2ms   pam_unix.so:
        Verifica contraseña Unix de carlos (PAM_AUTH)
        Si falla → DENY (no llega a pam_banexus.so)

T+3ms   pam_banexus.so (pam_authenticate):
        Lee el contexto: username, remote_ip, service="sshd"
        Abre el socket /run/banexus/pam.sock
        Envía shell_auth request a banexus:
          {
            "type":      "shell_auth",
            "node_id":   "Servidor-SSH-001",
            "user":      "carlos",
            "service":   "sshd",
            "remote_ip": "10.0.1.45",
            "ctx_id":    "<generado por banexus>",
            "timestamp": "RFC3339"
          }

T+4ms   banexus recibe shell_auth → reenvía auth_request a bhnexus (Puerta 1):
          {
            "type":            "auth_request",
            "node_id":         "Servidor-SSH-001",
            "user_credential": {
              "input_type":    "mtls_cert",
              "payload":       "<fingerprint del cert SSH de carlos>"
            },
            "domain":          "D09",
            "operation":       "remote_access.ssh",
            "ctx_id":          "<trace>",
            "timestamp":       "RFC3339"
          }

T+8ms   bhnexus → bAuth: bitmask_request domain=D09
T+12ms  bAuth evalúa:
        carlos.roles incluye ROL_SYSADMIN ✅
        ROL_SYSADMIN tiene átomo remote_access.ssh ✅
        IP 10.0.1.45 ∈ rango permitido ✅
        Hora: L 09:00 ✅
        Retorna SAM-128 con flag shell_sentinel=1

T+13ms  banexus retorna a pam_banexus.so: PAM_SUCCESS + ctx_id

T+14ms  pam_banexus.so (pam_open_session):
        Inyecta ctx_id como variable de entorno en la sesión SSH:
          export SBOS_CTX_ID="00-4a3b...-01"
        Registra apertura de sesión en banexus audit log

T+15ms  carlos tiene shell con el ctx_id inyectado
```

### 3.2 Si bhnexus retorna DENY

```
T+13ms  banexus retorna PAM_AUTH_ERR

T+14ms  pam_banexus.so:
        Registra el intento fallido:
          audit_event: {user:"carlos", action:"shell_auth", result:"denied", reason:"..."}
        Retorna PAM_AUTH_ERR a sshd
        sshd envía: "Permission denied, please try again."

        El usuario nunca llega a tener shell.
```

## 4. Auditoría de comandos durante la sesión

Una vez que el usuario tiene shell con `SBOS_CTX_ID` inyectado, el Shell Sentinel audita los comandos ejecutados.

### Mecanismo: execve hook via LD_PRELOAD o eBPF

**Opción A — LD_PRELOAD (banexus-shim.so)**:

```c
// banexus-shim.so — se precaraga en la sesión SSH con LD_PRELOAD
int execve(const char *pathname, char *const argv[], char *const envp[]) {
    // Leer el ctx_id del entorno
    const char *ctx_id = getenv("SBOS_CTX_ID");

    // Construir el registro del comando
    struct ShellEvent event = {
        .ctx_id    = ctx_id,
        .user      = getenv("USER"),
        .command   = pathname,
        .args      = argv,
        .cwd       = getcwd(NULL, 0),
        .pid       = getpid(),
        .timestamp = now_utc(),
    };

    // Enviar al daemon banexus (socket Unix no bloqueante)
    banexus_report_command(&event);

    // Llamar el execve real del kernel (continúa la ejecución del comando)
    return syscall(SYS_execve, pathname, argv, envp);
}
```

**Opción B — eBPF (configuración de alta seguridad, sl=4)**:

Para zonas sl=4, banexus usa un programa eBPF adjunto al tracepoint `sys_enter_execve`:
- Captura TODOS los execve en el namespace del usuario (no solo los que tienen LD_PRELOAD)
- Imposible evitar con `unset LD_PRELOAD`
- Requiere banexus con `CAP_BPF` + `CAP_PERFMON`

La elección entre LD_PRELOAD y eBPF es configurable en banexus.toml por zona.

## 5. Qué comandos generan alertas

banexus tiene una lista de **comandos de alto riesgo** que generan alertas en el SIEM (Wazuh):

```toml
[shell_sentinel.risk_commands]
critical = [
    "rm -rf /",
    "dd if=",
    "mkfs",
    "shred",
    "wipefs",
    "openssl genrsa",
    "vault seal",
    "vault operator unseal",
]

high = [
    "sudo",
    "su",
    "passwd",
    "chown",
    "chmod 777",
    "iptables",
    "systemctl stop",
    "systemctl disable",
    "apt-get install",
    "pip install",
    "cargo install",
    "curl * | bash",
    "wget * | bash",
]

medium = [
    "ssh",
    "scp",
    "rsync",
    "git push",
    "docker run",
    "kubectl",
    "psql",
]
```

### Respuestas automáticas por nivel de riesgo

| Nivel | Respuesta de banexus | Respuesta de bhnexus | Respuesta de bAuth |
|-------|---------------------|---------------------|-------------------|
| critical | Intercepta + consulta bAuth antes de ejecutar | Alerta SIEM inmediata | Puede emitir step_up_required |
| high | Log + alerta SIEM | Alerta SIEM | Registro en audit_events |
| medium | Log | — | — |

### Interceptación de comandos críticos

Para comandos marcados como `critical`, banexus puede **congelar** la ejecución y consultar a bAuth antes de permitirla:

```
usuario ejecuta: sudo rm -rf /var/lib/

banexus (execve hook) detecta "rm -rf"
  → Congela la llamada execve
  → Envía shell_auth request especial a bhnexus:
    {
      "type":      "shell_auth",
      "action":    "rm -rf /var/lib/",
      "risk_level": "critical",
      "requires_approval": true
    }
  → bAuth evalúa: ¿tiene el usuario APPROVE_DESTRUCTIVE_OP? ✅
  → Si SÍ: libera el execve con audit trail completo
  → Si NO: cancela el execve con EPERM, log + alerta SIEM
```

## 6. Cierre de sesión

Cuando la sesión SSH termina (normal o por timeout):

```
pam_banexus.so (pam_close_session):
  1. Notifica al daemon banexus: session_closed(ctx_id)
  2. banexus envía session_close al canal B de bhnexus
  3. bhnexus notifica a bAuth
  4. bAuth cierra el audit trail de la sesión:
     - Marca la sesión como cerrada en ses_context
     - Consolida los command_events en el audit log
     - Calcula duración total de la sesión
     - Si hubo alertas durante la sesión → dispara notificación a bOS
```

## 7. Configuración completa en banexus.toml

```toml
[shell_sentinel]
enabled = true

# Socket para comunicación con pam_banexus.so
pam_socket = "/run/banexus/pam.sock"

# Tiempo máximo que pam_banexus.so espera respuesta
# Si se supera → fail_open=false → DENY la sesión
pam_timeout_ms = 5000

# Método de auditoría de comandos
# "ld_preload" para zonas sl<4, "ebpf" para sl=4
audit_method = "ld_preload"

# Solo para audit_method="ebpf"
ebpf_namespace = "user"   # "user" | "host" (host audita TODOS los namespaces)

[shell_sentinel.risk_commands]
# Los comandos marcados como critical se interceptan (freeze + consult bAuth)
intercept_critical = true
# Los comandos de risk=high solo se loguean + SIEM
log_high = true
# Los de medium solo van al audit log local
log_medium = true
```

## 8. Servicios que usan pam_banexus.so

| Servicio | Archivo PAM | Qué verifica |
|---------|------------|--------------|
| sshd | `/etc/pam.d/sshd` | Acceso SSH remoto (D09 remote_access.ssh) |
| sudo | `/etc/pam.d/sudo` | Elevación de privilegios (D09 privilege_elevation) |
| login | `/etc/pam.d/login` | Acceso TTY local (D09 local_access) |
| su | `/etc/pam.d/su` | Cambio de usuario (D09 user_switch) |
| gdm/sddm | `/etc/pam.d/gdm` | Acceso gráfico al escritorio (D09 desktop_access) |
