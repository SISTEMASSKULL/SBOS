## 1. Qué es SAM-128

**SAM-128** (Sovereign Access Mask — 128 bits) es la estructura de autorización en caché de bhnexus. Es la respuesta serializada de bAuth, compactada en 128 bits, que bhnexus almacena en su Auth Cache para responder a banexus sin consultar bAuth en cada evento físico.

SAM-128 NO es una copia del BitMask 64-bit de bAuth. Es una **proyección especializada** del BitMask de bAuth, combinada con metadatos de contexto físico, optimizada para evaluación en tiempo O(1) en el mundo del hardware.

---

## 2. Estructura de 128 bits

```
SAM-128: dos palabras de 64 bits

[  63..0  ] → WORD-A: BitMask de privilegios físicos (64 átomos de acceso)
[ 127..64 ] → WORD-B: Contexto físico y metadatos de la sesión

WORD-A — Privilegios físicos (64 bits):
  Bit 0-7   → Nivel de acceso (0=sin acceso, 1=visitante, 2=empleado, 3=supervisor...)
  Bit 8-15  → Zonas autorizadas (bitmask, 8 zonas máx por SAM)
  Bit 16-23 → Tipos de credencial aceptados (QR, NFC, biométrico, smartcard...)
  Bit 24-31 → Actuadores autorizados (relé 0-7 que puede activar)
  Bit 32-39 → Restricciones horarias (ventanas de 3h, cubre 24h)
  Bit 40-47 → Políticas de anti-passback y Two-Person Rule
  Bit 48-55 → Step-up requirement (0=sin step-up, 1=segundo factor requerido)
  Bit 56-63 → Flags de estado (revocado, suspendido, en cuarentena...)

WORD-B — Contexto físico (64 bits):
  Bit 0-15  → TTL residual en segundos (max 65535s ≈ 18h)
  Bit 16-31 → Hash del RolTemplate que originó esta decisión (versión)
  Bit 32-47 → ID de zona física actual (para anti-passback)
  Bit 48-55 → LoA requerido para escalada (AAL1=1, AAL2=2, AAL3=3)
  Bit 56-63 → Flags de canal (mTLS required, ctx_id required, audit required)
```

> Ver `A.06_SAM128-MAPA-BITS.md` para el mapeo completo de cada bit con su átomo correspondiente en el BitMask 64-bit de bAuth.

## 3. Auth Cache de bhnexus

El Auth Cache es el almacén in-memory de SAM-128 en bhnexus.

```
Estructura:
  map[(user_id, node_id)] → CacheEntry {
      sam128:          Sam128,          // 128 bits de autorización
      actuator_cmds:   Vec<ActuatorCmd>, // comandos precomputados para GRANTED
      expires_at:      Instant,          // TTL absoluto
      roltemplate_hash: u16,             // versión del RolTemplate
  }

Capacidad:    10.000 entradas (configurable)
TTL:          30 segundos (por defecto — bAuth puede enviar TTL distinto por usuario)
Eviction:     LRU al llegar al límite de capacidad
Almacenamiento: solo RAM — jamás en disco (bhnexus no tiene persistencia propia)
```

### Latencias del cache

| Escenario | Flujo | Latencia |
|-----------|-------|---------|
| **Cache hit** | bhnexus → cache local → banexus | < 2ms |
| **Cache miss** | bhnexus → bAuth (Puerta 2A) → almacena → banexus | < 10ms |
| **Invalidación por policy_update** | bAuth → canal privilegiado → bhnexus invalida entrada | < 5ms |
| **Invalidación por TTL** | automática al expirar 30s | inmediata |

## 4. Evaluación en O(1)

La evaluación de una credencial contra el SAM-128 es una operación de tiempo constante. No hay consultas SQL, no hay joins, no hay llamadas de red.

```rust
/// Verifica si el SAM-128 autoriza el acceso al bit de privilegio solicitado.
/// Tiempo de evaluación: O(1) — operación bitwise pura.
pub fn evaluate(sam: Sam128, bit: PhysicalBit, ctx: EvalContext) -> Decision {
    // Verificar expiración (WORD-B bits 0-15)
    if sam.ttl_residual() == 0 {
        return Decision::Denied(DenyReason::Expired);
    }

    // Verificar revocación (WORD-A bit 56)
    if sam.word_a & REVOKED_FLAG != 0 {
        return Decision::Denied(DenyReason::Revoked);
    }

    // Verificar el bit de privilegio solicitado (WORD-A)
    if sam.word_a & (1u64 << bit as u8) != 0 {
        // Verificar restricciones de zona (WORD-A bits 8-15)
        if !sam.zone_allows(ctx.zone_id) {
            return Decision::Denied(DenyReason::ZoneRestricted);
        }
        // Verificar ventana horaria (WORD-A bits 32-39)
        if !sam.schedule_allows(ctx.current_hour) {
            return Decision::Denied(DenyReason::OutsideSchedule);
        }
        Decision::Granted
    } else {
        Decision::Denied(DenyReason::InsufficientPrivilege)
    }
}
```

## 5. Invalidación del cache

El SAM-128 puede quedar inválido por tres razones. Cada una tiene su mecanismo:

| Causa | Mecanismo | Latencia de invalidación |
|-------|-----------|------------------------|
| **TTL expirado** | Verificación automática en cada acceso | Inmediata al consultar |
| **RolTemplate cambiado** | bAuth → canal privilegiado → `policy_sync` con `roltemplate_hash` nuevo | < 5ms (canal privilegiado) |
| **Revocación de emergencia** | bAuth → canal privilegiado → `emergency_revoke` con `user_id` | < 5ms |
| **Blacklist de nodo** | bAuth → canal privilegiado → `blacklist_node` con `node_id` | < 5ms |
| **Reconexión de banexus** | bhnexus invalida todas las entradas del nodo al reconectarse | inmediata |

## 6. Relación con el BitMask 64-bit de bAuth

El BitMask 64-bit de bAuth (campo `rol_bitmask` en `idn_roles_template`) es el mapa de todos los átomos de privilegio de un usuario en el sistema de identidad. Tiene 64 posiciones, una por átomo.

SAM-128 es una **proyección** del BitMask de bAuth adaptada al dominio físico:

```
BitMask 64-bit de bAuth (plano de identidad):
  Bit 0  → D00.ATOM.001 (identidad organizacional - leer)
  Bit 1  → D00.ATOM.002 (identidad organizacional - escribir)
  ...
  Bit 44 → D93.ATOM.001 (acceso físico - zona A)
  Bit 45 → D93.ATOM.002 (acceso físico - zona B)
  ...
  Bit 63 → D15.ATOM.NNN (dominio blockchain)

SAM-128 WORD-A (proyección física):
  Bit 0-7  → nivel_acceso  → derivado de D93.ATOM.nivel
  Bit 8    → zona_A        → D93.ATOM.001 del BitMask
  Bit 9    → zona_B        → D93.ATOM.002 del BitMask
  ...
  Bit 24   → relay_01      → D93.ATOM.relay_01
  ...
```

La proyección la hace bAuth al construir la respuesta de Puerta 2A. bhnexus recibe el SAM-128 ya construido y lo almacena — no tiene acceso al BitMask completo de bAuth.

## 7. SAM-128 en el Policy Cache de banexus

banexus tiene su propio Policy Cache local — una copia del último SAM-128 recibido, cifrada en disco con AES-256-GCM.

```
PolicyCache de banexus:
  user_id:      UserId          // a quién corresponde
  sam128:       Sam128          // 128 bits cifrados en disco
  received_at:  Instant         // cuándo se recibió
  ttl:          Duration        // máximo 4h (configurable)
  key:          DerivedKey      // HKDF-SHA256 derivada del cert mTLS del nodo

Uso en modo offline:
  → si TTL vigente: evalúa localmente en O(1) sin consultar bhnexus
  → si TTL expirado: DENY (fail-secure)
  → al reconectar: invalida toda la cache, solicita SAM fresco a bhnexus
```

La clave de cifrado se deriva del certificado mTLS del nodo banexus (HKDF-SHA256). Si el disco es robado sin el certificado, el cache es ilegible.

## 8. Garantías del SAM-128

| Garantía | Descripción |
|----------|-------------|
| **Consistencia eventual** | SAM-128 puede estar desactualizado hasta 30s (TTL) en condiciones normales |
| **Consistencia urgente** | `emergency_revoke` via canal privilegiado invalida en < 5ms |
| **Offline seguro** | Policy Cache de banexus opera hasta 4h; falla cerrado si vence |
| **Sin persistencia de bhnexus** | Auth Cache de bhnexus solo en RAM — reinicio limpia todo |
| **Auditoría completa** | Todo cache hit/miss registrado con `ctx_id` + `node_id` + `ts` en `audit_events` |
