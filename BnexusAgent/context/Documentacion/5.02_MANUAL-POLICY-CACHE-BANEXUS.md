# 5.02 — Policy Cache de banexus
## AES-256-GCM en disco, TTL 4h, clave HKDF-SHA256, fail-secure en expiración

**Versión:** 1.0.0  
**Fecha:** 2026-08-04  
**Fuente:** SBOS-NEXUS-CONCEPTUALIZACION-v3_0.md §12  
**Carta rectora:** `0.00_MANUAL-DIRECTRICES-NEXUS.md`  

---

## 1. Propósito

El Policy Cache de banexus es el cache local del agente de borde. Su función es permitir que banexus evalúe credenciales durante períodos de desconexión con bhnexus, con las siguientes garantías:

1. **Confidencialidad**: las políticas en disco están cifradas — no se pueden leer sin la clave del nodo
2. **Integridad**: la autenticación AES-GCM detecta cualquier modificación del archivo
3. **Frescura**: el cache expira después de 4h — una política vieja no se usa indefinidamente
4. **Fail-secure**: si el cache expira y no hay conexión, banexus deniega todo acceso

---

## 2. Diferencia con el Auth Cache de bhnexus

| Aspecto | Auth Cache (bhnexus) | Policy Cache (banexus) |
|---------|---------------------|----------------------|
| Ubicación | Memoria RAM | Disco (cifrado) |
| Sobrevive restart | No | Sí (mientras TTL vigente) |
| Sobrevive offline | N/A (es el servidor) | Sí — ese es su propósito |
| TTL | 30 segundos | 4 horas |
| Capacidad | 10.000 entradas | Toda la zona del nodo |
| Cifrado | No | AES-256-GCM |

---

## 3. Derivación de la clave de cifrado

La clave que protege el Policy Cache se deriva del certificado mTLS del nodo. Esto garantiza que el cache solo puede ser descifrado por el nodo legítimo — robar el archivo de disco no sirve sin el certificado.

### Derivación con HKDF-SHA256

```
Input key material (IKM): clave privada ECDSA P-256 del cert SPIFFE del nodo
                          (almacenada en /run/bos/certs/banexus.key)

Salt: node_id del nodo (string bytes)

Info: "banexus-policy-cache-v1" (contexto)

Output: 32 bytes → clave AES-256

Código Rust:
    use hkdf::Hkdf;
    use sha2::Sha256;

    let hk = Hkdf::<Sha256>::new(Some(node_id.as_bytes()), &private_key_bytes);
    let mut cache_key = [0u8; 32];
    hk.expand(b"banexus-policy-cache-v1", &mut cache_key)
      .expect("HKDF expand no puede fallar con 32 bytes");
```

### Cuándo rederiva la clave

```
La clave se rederiva EN MEMORIA al arrancar banexus — no se almacena en disco.

Flujo:
  1. banexus arranca → lee cert privado de /run/bos/certs/banexus.key
  2. Deriva la clave AES con HKDF-SHA256 (en memoria)
  3. Intenta abrir el Policy Cache con esa clave
  4. Si el cert rotó (clave privada nueva) → el decrypt falla (tag GCM inválido)
     → banexus borra el cache y solicita un nuevo paquete de políticas a bhnexus
```

## 4. Formato del archivo de cache

```
Archivo: /var/lib/banexus/policy_cache.enc

Estructura binaria:
  [4 bytes]  Número mágico: 0x424E5843 ("BNXC")
  [4 bytes]  Versión del formato: uint32 BE = 1
  [8 bytes]  Timestamp de creación: uint64 BE = Unix timestamp (segundos)
  [8 bytes]  TTL en segundos: uint64 BE = 14400 (4h)
  [12 bytes] Nonce AES-GCM: 96 bits aleatorios (generados al cifrar)
  [4 bytes]  Longitud del ciphertext: uint32 BE
  [N bytes]  Ciphertext AES-256-GCM del payload JSON
  [16 bytes] Tag de autenticación AES-GCM (al final del ciphertext en la convención de RustCrypto)

Total overhead: 56 bytes + 16 bytes GCM tag = 72 bytes + ciphertext
```

### Payload JSON (plaintext antes de cifrar)

```json
{
  "version":           1,
  "node_id":           "string",
  "generated_at":      "RFC3339",
  "ttl_seconds":       14400,
  "roltemplate_hash":  "0x<hex4>",
  "policies": {
    "users": {
      "<user_id>": {
        "sam128": {
          "word_a": "0x<hex16>",
          "word_b": "0x<hex16>"
        },
        "credential_types_allowed": ["nfc", "smartcard", "pin"],
        "actuator_commands": [
          { "target": "RELAY_01", "action": "PULSE", "duration_ms": 5000 }
        ],
        "schedule": {
          "days":  "L-V",
          "start": "07:00",
          "end":   "20:00",
          "tz":    "America/La_Paz"
        }
      }
    },
    "zone_config": {
      "security_level":  2,
      "fail_mode":       "fail_secure",
      "credential_types_allowed": ["nfc", "qr", "smartcard", "pin"]
    }
  }
}
```

## 5. Ciclo de vida del cache

### 5.1 Creación (primera conexión o S-04 recovery)

```
1. bhnexus envía auth_response con policies completas
2. banexus recibe el paquete de políticas
3. Genera nonce aleatorio (12 bytes, CSPRNG)
4. Cifra el payload JSON con AES-256-GCM
5. Escribe el archivo en /var/lib/banexus/policy_cache.enc
6. Establece mtime del archivo = ahora (para verificación de expiración)
```

### 5.2 Uso durante operación normal

```
banexus recibe auth_request del hardware:
  → Intenta consultar bhnexus (Puerta 1) con latencia < 50ms
  → Si OK → responde con el resultado de bhnexus (no usa el cache local)

El Policy Cache LOCAL solo se usa cuando bhnexus es inaccesible.
Durante operación normal, es un respaldo dormido — no la fuente primaria.
```

### 5.3 Uso durante offline

```
Conexión con bhnexus perdida:
  → banexus abre /var/lib/banexus/policy_cache.enc
  → Verifica el header (magic number + version)
  → Verifica que now() - timestamp < ttl_seconds
  → Si expirado → FAIL-SECURE: deniega todo acceso (ver §6)
  → Si vigente → descifra con la clave derivada en memoria
  → Verifica el tag GCM (si falla → el archivo fue modificado → FAIL-SECURE)
  → Sirve auth_request desde el payload JSON descifrado
```

### 5.4 Actualización (policy_update desde bhnexus)

```
bhnexus envía policy_update con user_ids afectados:
  → banexus descifra el cache actual
  → Actualiza las entradas de los usuarios afectados
  → Re-cifra con un nuevo nonce (NUNCA reutilizar nonces en GCM)
  → Escribe el archivo actualizado
  → El TTL se REINICIA (nueva creación, 4h desde ahora)
```

## 6. Fail-secure en expiración

Esta es la garantía más crítica del Policy Cache:

> **Si el cache expiró y no hay conexión a bhnexus → DENY a todo acceso, sin excepción.**

```
Justificación:
  Una política de 4h de antigüedad puede contener:
  - Usuarios que han sido revocados en bAuth
  - Roles que han cambiado
  - Eventos de seguridad que bAuth no pudo notificar
  
  Usar una política expirada es más peligroso que no tener acceso.
  La seguridad física prioriza negar acceso no verificable.
  
  Excepción: para zonas con fail_mode = "fail_safe" (ruta de evacuación),
  la CERRADURA se abre físicamente (no por decisión de banexus) — 
  banexus igual deniega, pero la puerta no bloquea físicamente.
```

### Respuesta cuando el cache está expirado

```json
{
  "type":        "auth_response",
  "request_id":  "<uuid>",
  "status":      "denied",
  "deny_reason": "policy_cache_expired",
  "deny_message": "Política de acceso expirada. El dispositivo debe reconectar para renovar políticas.",
  "offline_mode": true,
  "cache_age_s":  15200,
  "timestamp":    "<RFC3339>"
}
```

## 7. Seguridad del archivo en disco

```
Permisos del archivo: 0600
Owner: banexus (usuario del proceso banexus)
Grupo: bos

Medidas adicionales:
  - El directorio /var/lib/banexus/ tiene permisos 0700
  - El archivo solo existe mientras el proceso está instalado
  - Al desregistrar un nodo (bhnexus.node.deregister), bOS envía señal a banexus
    para que borre el archivo de cache antes de desactivarse

Amenazas mitigadas:
  Robo físico del disco   → el ciphertext es inútil sin el cert + clave privada
  Modificación del archivo → el tag GCM detecta cualquier cambio de 1 bit
  Ataque de replay         → el timestamp en el header invalida caches transplantados
```

## 8. Rotación de certificados y el cache

Cuando el certificado mTLS de banexus rota (cada 90 días por defecto en Vault):

```
1. bOS emite el nuevo cert para el node_id (mismo SPIFFE ID, nueva clave privada)
2. banexus descarga el nuevo cert (por bOS provisioning)
3. banexus redvive: rederiva la clave HKDF con la nueva clave privada
4. Intenta descifrar el cache existente con la nueva clave → falla (tag GCM inválido)
5. banexus detecta el fallo → borra el cache anterior
6. Se conecta a bhnexus y solicita un nuevo paquete de políticas (S-01 P3)
7. Nuevo cache cifrado con la nueva clave

Tiempo de indisponibilidad del cache durante rotación: < 2s (tiempo de S-01)
```
